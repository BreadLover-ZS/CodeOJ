## 1. 前端工程结构

```text
codeoj-frontend/
├── public/
├── src/
│   ├── access/            # 前端权限体系（权限枚举 + 校验函数 + 路由守卫)
│   ├── components/        # 通用组件（代码编辑器、Markdown 编辑器/查看器、页头）
│   ├── layouts/           # 布局（UserLayout 登录页布局 / BasicLayout 主布局）
│   ├── plugins/           # axios 请求封装
│   ├── router/            # 路由（routes 定义 + index 创建实例）
│   ├── store/             # Vuex（用户登录态）
│   ├── views/             # 页面（用户、题目、提交记录、管理端）
│   ├── generated/         # OpenAPI 自动生成的 TS 接口客户端（不要手改）
│   ├── App.vue
│   └── main.ts            # 入口
├── vue.config.js          # dev 端口 8000、代理配置
└── package.json
```

关键点：前端调后端**不直接打服务端口**，而是打 **网关 8101**（见 `generated/core/OpenAPI.ts` 里 `BASE: 'http://localhost:8101'`，且 `WITH_CREDENTIALS: true` 保证跨域带 cookie）。

## 2. 请求层（axios 与 OpenAPI 生成代码）

[axios.ts](file:///e:/gitStore/ZSOJ/codeoj-frontend/src/plugins/axios.ts) 做了两件事：

- `axios.defaults.withCredentials = true`：跨域请求携带 Cookie（登录态靠它）。
- 注册请求/响应拦截器（目前只是透传，可自行扩展统一错误提示）。

实际接口调用来自 `src/generated/` 目录，这是用 OpenAPI 从后端 Swagger 自动生成的 TypeScript 客户端（`UserControllerService`、`QuestionControllerService` 等），**任意接口都被封装成 Promise 方法**，页面里直接 `await xxxService.yyy(...)` 即可，不需要手写 URL。

## 3. 登录态与权限（access/ + store/）

前端权限体系分三层配合：

### 3.1 权限枚举 [accessEnum.ts](file:///e:/gitStore/ZSOJ/codeoj-frontend/src/access/accessEnum.ts)

```ts
const ACCESS_ENUM = {
  NOT_LOGIN: "notLogin", // 未登录
  USER: "user",          // 普通用户
  ADMIN: "admin",        // 管理员
  BAN: "ban",            // 封号
};
```

### 3.2 权限校验 [checkAccess.ts](file:///e:/gitStore/ZSOJ/codeoj-frontend/src/access/checkAccess.ts)

传入当前登录用户和页面要求权限，返回能否访问。规则：

- 要求 `notLogin`：都放行。
- 要求 `user`：未登录或封号用户被拒。
- 要求 `admin`：非 admin 一律拒绝（封号同理）。

### 3.3 路由守卫 [access/index.ts](file:///e:/gitStore/ZSOJ/codeoj-frontend/src/access/index.ts)

`router.beforeEach` 全局前置守卫，每次跳转前：

1. 若 store 里还没有用户角色，先 `await store.dispatch("user/getLoginUser")` 拉取登录态。
2. 读取目标路由 `meta.access`（默认 `notLogin`）。
3. 需要登录的页面：未登录 → 跳 `/user/login?redirect=xxx`（登录后回跳）；已登录但权限不足 → 跳 `/noAuth`。

### 3.4 登录态存储 [store/user.ts](file:///e:/gitStore/ZSOJ/codeoj-frontend/src/store/user.ts)

Vuex 的 `user` 模块，`getLoginUser` action 调 `UserControllerService.getLoginUserUsingGet()` 从后端拉当前登录用户，成功后写入 store。**注意：前端 store 只是缓存的镜像，真正的权威登录态在后端 Redis Session 里**。

## 4. 路由表 [routes.ts](file:///e:/gitStore/ZSOJ/codeoj-frontend/src/router/routes.ts)

| 路径 | 页面 | 权限 |
|---|---|---|
| `/user/login`、`/user/register` | 登录 / 注册（UserLayout 布局） | 公开 |
| `/questions` | 题目列表；`/` 直接复用同一页面组件 | 公开 |
| `/question_submit` | 全部提交记录 | 公开 |
| `/view/question/:id` | 在线做题（题目+编辑器） | 登录 |
| `/add/question` | 创建题目 | 登录 |
| `/update/question` | 更新题目（隐藏菜单） | 登录 |
| `/manage/question/` | 管理题目 | 管理员 |
| `/manage/user` | 管理用户 | 管理员 |
| `/noAuth` | 无权限提示页 | 公开（隐藏菜单） |

## 5. 四个重要页面/组件

### 5.1 做题页 [ViewQuestionView.vue](file:///e:/gitStore/ZSOJ/codeoj-frontend/src/views/question/ViewQuestionView.vue)

左右分栏布局：

- **左栏**：题目标题、标签（tags）、时间/内存/堆栈限制（来自 `judgeConfig`）、题目内容（`MdViewer` 渲染 Markdown）。
- **右栏**：语言选择（java/cpp/go）+ [CodeEditor.vue](file:///e:/gitStore/ZSOJ/codeoj-frontend/src/components/CodeEditor.vue)（Monaco Editor 封装）+ 提交按钮。

点「提交代码」调用 `QuestionControllerService.doQuestionSubmitUsingPost(...)`，传 `{ questionId, language, code }`，**后端立即返回的是“提交记录 id”（long），不是判题结果**。判题结果是异步的，需隔一段时间查提交列表接口获取 status 和 judgeInfo。

### 5.2 题目列表 [QuestionsView.vue](file:///e:/gitStore/ZSOJ/codeoj-frontend/src/views/question/QuestionsView.vue)

卡片网格展示题目（标题、标签、提交/通过数），分页查询 `QuestionVO`（脱敏版，不含答案和用例）。

### 5.3 提交记录 [QuestionSubmitView.vue](file:///e:/gitStore/ZSOJ/codeoj-frontend/src/views/question/QuestionSubmitView.vue)

表格展示每条提交的语言、状态（待判题/判题中/成功/失败）、耗时、内存、判题信息，翻页查询 `QuestionSubmitVO`。**普通用户看别人的提交，代码字段会被后端脱敏置空**（`getQuestionSubmitVO` 里的处理）。

### 5.4 管理页 [ManageQuestionView.vue](file:///e:/gitStore/ZSOJ/codeoj-frontend/src/views/question/ManageQuestionView.vue) / [AdminUserManageView.vue](file:///e:/gitStore/ZSOJ/codeoj-frontend/src/views/user/AdminUserManageView.vue)

管理员增删改题目（含用例 judgeCase、判题配置 judgeConfig 的 JSON 编辑）、管理用户角色（升管理员/封号）。

## 6. 前端 FAQ

**Q1：为什么改代码前端调用后端要经过网关而不是直连服务端口？**
答：统一入口做路由分发、CORS、内部接口拦截；业务服务端口不对外暴露，避免绕过网关的鉴权防护。

**Q2：跨域怎么解决的？**
答：前端 8000，网关 8101。`vue.config.js` 里 dev 代理转发 + 网关 `CorsConfig` 配置白名单 + `withCredentials` 带 Cookie。

**Q3：为什么提交后页面不显示结果？**
答：判题是异步的（MQ），提交接口只返回记录 id，前端需要轮询查询提交接口直到状态变为终态（SUCCEED/FAILED），再解析 `judgeInfo.message` 展示 Accepted / WA / TLE 等。
