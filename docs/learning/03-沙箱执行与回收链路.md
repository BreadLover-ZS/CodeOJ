# 链路三：从执行请求到用户程序停止与资源回收

上条链的 worker 已领取 S1，持有代码、测试输入、资源限制、token T1 与期限。本链展开它调用沙箱后的内部过程，最后把运行输出和资源结果交回判题端，同时解释物理执行如何收尾。

## 全局位置：数据库执行权之外，还有真实进程

```text
判题 worker → HTTP → 沙箱 Controller / 执行管理器
  → 登记 T1、申请物理 slot
  → 编译容器 → 只读 class 产物
  → case-0 新容器 → case-1 新容器 → …
  → 收集输出与受信结果 → 清理容器/卷 → 持久结果与 slot 状态
  ← 返回 ExecuteCodeResponse → 判题策略比较答案 → 题目服务保存判定
```

沙箱不是在业务 JVM 内简单调用用户方法。管理器编排隔离进程，监督器在容器内执行期限与收据控制，用户程序以受限身份运行。题目服务的 token 管结果生效，监督器管程序停止，registry 管物理对象与容量。

| 配置或数据 | 先理解它的职责 |
| --- | --- |
| 判题端 type=remote | HTTP 调用方式 |
| 沙箱端 mode=isolated | 容器执行方式，默认模式；与 remote 可同时成立 |
| ExecuteCodeRequest | 代码、语言、inputList、资源限制、T1、绝对期限 |
| ExecuteCodeResponse | outcome/status、outputList、judgeInfo 与诊断 |
| slot | 沙箱物理并发名额，不是 worker 的本地 Semaphore |
| 持久登记 | token/hash/期限/slot/状态/响应，供重复请求与管理器恢复 |

协议类型对照：[ExecuteCodeRequest](../../codeoj-backend/codeoj-backend-model/src/main/java/com/codeoj/codeojbackendmodel/model/codesandbox/ExecuteCodeRequest.java) 与 [ExecuteCodeResponse](../../codeoj-backend/codeoj-backend-model/src/main/java/com/codeoj/codeojbackendmodel/model/codesandbox/ExecuteCodeResponse.java)；先把 worker 构造值与执行端读取值一一对应。

第一遍假设请求合法、资源够、两个用例正常结束、清理成功。期望输出不传给沙箱，答案比较仍在链路二。

## 第一遍：正常执行

### 1. worker 怎样到达沙箱服务

源码：[RemoteCodeSandbox.executeCode](../../codeoj-backend/codeoj-backend-judge-service/src/main/java/com/codeoj/codeojbackendjudgeservice/judge/codesandbox/impl/RemoteCodeSandbox.java)。

**阅读范围：** 从 HTTP 请求构造读到响应解析，关注 URL、auth、连接/读取/总超时、响应大小与并发；先沿成功返回路径。

这是跨进程 HTTP，不能把它当作普通本地方法。客户端用受限调用池和有界响应读取，返回 ExecuteCodeResponse；没有透明地重跑代码。

源码：[ExecuteCodeController.executeCode](../../codeoj-backend/codeoj-backend-codesandbox/src/main/java/com/codeoj/codeojbackendcodesandbox/controller/ExecuteCodeController.java)。

**阅读范围：** 先看 checkAuth 再看委托执行；对照 CodeSandboxService，确认当前条件 Bean 是 JavaIsolatedCodeSandbox。

auth 保护执行接口。通过后才调用执行服务；它与业务内部 X-Inner-Secret 不同，也不是用户会话 Cookie。

### 2. 校验参数，经 registry 管理本次执行

源码：[JavaIsolatedCodeSandbox.executeCode/valid](../../codeoj-backend/codeoj-backend-codesandbox/src/main/java/com/codeoj/codeojbackendcodesandbox/service/impl/JavaIsolatedCodeSandbox.java)。

**阅读范围：** 读参数边界和 registry.execute 调用，随后进入 registry；先不深入 executeOnce。

语言、源码、输入数量/总量、资源限制都必须符合执行策略。题目规格校验与沙箱策略校验不在同一层：即使题目记录存在，执行端仍要拒绝不支持的请求。

源码：[DurableExecutionRegistry.execute](../../codeoj-backend/codeoj-backend-codesandbox/src/main/java/com/codeoj/codeojbackendcodesandbox/service/impl/DurableExecutionRegistry.java)。

**阅读范围：** 从 token/绝对期限检查读到内容摘要、已有记录查询、slot 申请、两份登记保存与 run 调用；第一遍假设没有旧 token 且有空位。

registry 把 T1 与请求摘要关联，持久登记后才允许创建物理对象。slot 限制同池同时执行的数量。这里既有文件锁也有持久 slot 记录，单独一个内存计数无法在管理器被杀后还原占用。

**当前进度：** 数据库已授予逻辑执行权，沙箱又确认执行身份并保留物理名额；接下来才真正启动编译和用户进程。

### 3. 编译一次，获得产物与入口

源码：[JavaIsolatedCodeSandbox.executeOnce](../../codeoj-backend/codeoj-backend-codesandbox/src/main/java/com/codeoj/codeojbackendcodesandbox/service/impl/JavaIsolatedCodeSandbox.java)。

**阅读范围：** 先从 token 工作目录、Submission.java 写入读到编译容器创建、upload/start、trustedResult 和 NativeReceipt；暂时停在用例循环之前。

管理器将代码写入 T1 专属工作目录，创建编译相关卷与容器，调用受信 NativeCompiler。编译产物与入口收据是后续运行依据，随机 nonce 用于核验编译收据。

编译成功不等于答案正确，只表示可以进入运行。明确用户语法错误是 CE；编译基础设施或阶段预算异常不能一概当成 CE。

### 4. 每个用例创建独立运行容器

回到 [JavaIsolatedCodeSandbox.executeOnce](../../codeoj-backend/codeoj-backend-codesandbox/src/main/java/com/codeoj/codeojbackendcodesandbox/service/impl/JavaIsolatedCodeSandbox.java)，读 inputList 循环：case 期限、case-i-receipt、容器创建、stdin 写入与执行结果读取。

源码：[DockerIsolationEngine.create/start](../../codeoj-backend/codeoj-backend-codesandbox/src/main/java/com/codeoj/codeojbackendcodesandbox/service/impl/DockerIsolationEngine.java)。

**阅读范围：** create 看 artifact 挂载、readOnlyArtifacts、网络/身份/资源参数与监督器入口，start 看有界进程调用。

class 只编译一次，每个用例使用新容器，运行产物只读，可写空间不在用例间复用。例如 case-0 输入 1 2 得到 3，case-1 输入 5 8 得到 13。上一用例的文件和残留进程不应成为下一用例初始状态。

底层管理器调用 Docker，用户容器不挂 Docker socket、业务凭据或宿主业务目录。受信管理器能访问 daemon，不能据此说用户代码也能访问它。

### 5. 谁运行程序、计时、清理后代并生成结果

源码：[supervisor.py](../../codeoj-backend/codeoj-backend-codesandbox/isolation/supervisor.py) 的 unprivileged、main。

**阅读范围：** 从阶段预算/绝对期限取较早值读起，跟到降 UID/GID、Popen、wait、后代清理、cgroup 指标与私有结果文件。先走正常退出分支。

监督器与用户程序在同一隔离环境中，但承担不同职责。用户 Java 降为 UID/GID 10000，控制收据由受信监督器生成；stdout 是答案数据，不能靠用户打印 JSON 来宣布“已经安全结束”。

| 风险 | 具体阅读位置与控制 |
| --- | --- |
| 网络访问 | engine.create 的 network none |
| 写宿主或产物 | 挂载范围、read-only、只读运行产物 |
| 内存/CPU/PID | cgroup memory/cpus/pids 参数与观测 |
| 临时文件和描述符 | tmpfs 与 ulimit |
| 输出无界 | BoundedProcessRunner 的双流读取与输出预算 |
| 死循环与后代逃逸运行 | supervisor 的期限和 namespace 后代清理 |

容器中的受信部分与用户降权进程应分开理解。当前机制不等于完成内核逃逸认证。

### 6. 管理器怎样判断一次用例的结果

源码：[JavaIsolatedCodeSandbox.trustedResult/executeOnce](../../codeoj-backend/codeoj-backend-codesandbox/src/main/java/com/codeoj/codeojbackendcodesandbox/service/impl/JavaIsolatedCodeSandbox.java)。

**阅读范围：** 先看 trustedResult 如何核验进程/容器状态和私有收据，再回用例循环的 end 分支及指标汇总。

执行器结合 OOM/退出状态与受信结果，区分 MLE、TLE、OUTPUT_LIMIT、RE、EXECUTED 和平台异常。缺关键资源观测不能编成 0 继续 AC。

多个用例的 time、memory 按当前实现取观测最大值。时间包含 JVM 启动；内存是用例 cgroup 的观测，包含 JVM、监督器和后代，不等于 Java 堆大小。

正常完成后带 outputList 与资源指标回到 registry。标准答案仍在 worker 领取的固定规格中，下一步交给链路二的策略比较。

### 7. 返回之前，物理对象怎样清理

源码：[DurableExecutionRegistry.run](../../codeoj-backend/codeoj-backend-codesandbox/src/main/java/com/codeoj/codeojbackendcodesandbox/service/impl/DurableExecutionRegistry.java)。

**阅读范围：** 跟 work.execute 返回后 engine.removeExecution、登记 response/state 和 slot 记录删除；先沿 cleaned=true。

源码：[DockerIsolationEngine.removeExecution](../../codeoj-backend/codeoj-backend-codesandbox/src/main/java/com/codeoj/codeojbackendcodesandbox/service/impl/DockerIsolationEngine.java)。

**阅读范围：** 按 token 的 label 定位所属容器与卷，跟踪实际删除及失败传播。

正常工作结果不等于物理对象已消失。registry 确认清理成功，保存 COMPLETED、删除 slot 占用记录，再返回响应。finally 释放文件锁不表示所有残留都已清除，持久 slot 状态还必须正确。

**回到全局：** worker 得到运行输出，继续生成用户判定并向题目服务 complete。数据库的 COMPLETED 与 registry 的 COMPLETED 属于两个状态对象，不能只看同名字符串就认为是一回事。

## 第二遍：运行和管理器出问题时

### 8. HTTP 超时是否就是用户 TLE

回到 RemoteCodeSandbox 的总调用期限与取消，再对照 executeOnce/supervisor 的用例期限。HTTP 超时只说明调用方没有拿到可信响应，远端可能还在运行；用户 TLE 需要执行层明确超限依据。

不能在 HTTP 客户端透明换 token 再执行一次。数据库恢复状态机决定新尝试，旧物理执行还需监督器和回收管理。

### 9. 同 token 重复请求会怎样

回到 registry.execute 的 existing 分支：同 T1 同摘要可以在有限保留窗口内等待或回放；同 token 换内容拒绝。身份过期且没有可回放记录时，不新建执行。

按原 token 登记和本地恢复是沙箱的有限保证，不是对任意历史 token 永久提供 exactly-once。记录保留与 registry 容量也有明确边界。

### 10. 管理器被杀，谁让用户程序停下来

监督器独立执行阶段预算与总期限，即使管理器或 HTTP 调用方退出，也不能把用户进程的停止完全寄托在客户端超时。

源码：[JavaIsolatedCodeSandbox.recoverExecutions](../../codeoj-backend/codeoj-backend-codesandbox/src/main/java/com/codeoj/codeojbackendcodesandbox/service/impl/JavaIsolatedCodeSandbox.java)。

**阅读范围：** 从定时入口跟到 registry.recover；再看 recover/reap 如何取得 slot 锁并清理旧对象。

持久登记让后继管理器知道 T1 的物理对象与占用。新管理器取得恢复权后清理，不能仅因数据库租约过期就假设容器已经停止或名额空闲。

### 11. 删除失败为什么必须继续占名额

回到 registry.run 的 cleaned=false 与 reap：保存 REAP_PENDING 和持久 slot，返回清理待完成的平台结果，后续重试清理。

假设总容量 2，T1 的结果已算出但删除失败，另一个名额空闲，此时可用只有 1。归还逻辑执行权、本地 Semaphore、沙箱 slot 的时机不同。

### 12. 多管理器与共享范围有什么限制

读 registry 构造时的配置校验、共享文件通道、锁获取、slot 日志、损坏处理与 collect。多个管理器共享容量要求同一 daemon、同一持久本地目录和一致策略；损坏登记保守处理，不随意释放容量。

不能删除活跃锁文件来“重置”；不能把这个池外推为任意多宿主机的全局调度。宿主断电恢复等也按证据边界表达。

### 13. 为什么仍保留 native

源码：[JavaNativeCodeSandbox.executeCode](../../codeoj-backend/codeoj-backend-codesandbox/src/main/java/com/codeoj/codeojbackendcodesandbox/service/impl/JavaNativeCodeSandbox.java) 与 [BoundedProcessRunner](../../codeoj-backend/codeoj-backend-codesandbox/src/main/java/com/codeoj/codeojbackendcodesandbox/service/impl/BoundedProcessRunner.java)。

**阅读范围：** 用它理解编译文件、stdin、双流读取、退出与预算；知道用途后返回 isolated 主链。

native 是显式可信样例模式，有有界 I/O 和资源观测，但不具备 isolated 的 Linux 容器边界。isolated 条件缺失时拒绝启动，不自动降级。具体环境见[隔离说明](../contest/isolated-sandbox.md)。

## 阅读成果与测试

1. 画“远程请求 → 登记 → 编译 → 逐用例运行 → 收据 → 清理 → 返回”的时序，标出真实进程边界。
2. 对无输出死循环、持续输出、管理器被杀三种场景，分别指出期限、结果和清理由谁负责。
3. 解释 DB token、worker 名额、物理 slot、registry 状态各保护什么。

核对：数据库拒绝旧结果不能代替物理停止；HTTP 返回不能代替删除确认；用户输出不能代替受信收据。
