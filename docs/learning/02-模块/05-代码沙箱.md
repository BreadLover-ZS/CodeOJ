# 代码沙箱：执行、资源限制与回收

**阅读目标：** 读完应能从 HTTP 请求跟到用户进程，并解释超时、管理器退出和清理失败时的资源归属。

沙箱接收代码和输入，返回执行结果；答案是否正确由判题策略比较。当前默认 `isolated`，按编译尝试和测试用例隔离；`native` 是显式可信样例模式。

## 2. 先看请求和响应

请求模型见 [ExecuteCodeRequest](../../../codeoj-backend/codeoj-backend-model/src/main/java/com/codeoj/codeojbackendmodel/model/codesandbox/ExecuteCodeRequest.java)：代码、语言、输入列表、时间/内存限制，以及 `executionToken`、绝对执行期限。

响应模型见 [ExecuteCodeResponse](../../../codeoj-backend/codeoj-backend-model/src/main/java/com/codeoj/codeojbackendmodel/model/codesandbox/ExecuteCodeResponse.java)：`outcome`、输出、资源指标和诊断字段。消费方还会检查 status/outcome 一致性，不能只看是否返回了 JSON。

`EXECUTED` 只说明执行完成，还需比较答案。平台错误不是用户 RE/TLE；缺少必要资源指标时也不能填 0 后认定 AC。

## 3. 一次 isolated 执行

```text
校验 token/期限 → 登记并占用 slot → 独立编译容器
              → 只读编译产物 → 每个用例一个新容器
              → 监督器采集退出/资源/输出结果 → 清理容器和卷 → 保存结果、释放 slot
```

编译一次，多个用例分别运行；可写空间不在用例间复用。监督器负责阶段预算和总期限，用户输出只是答案数据，不能伪造监督器的私有控制收据。

## 4. 约束落在哪里

| 边界 | 当前控制 |
| --- | --- |
| 身份 | 用户 Java 以 UID/GID 10000 运行，清空 capabilities；监督器是独立受信部分 |
| 网络与挂载 | 用户容器禁网，不挂宿主业务目录、服务凭据或 Docker socket |
| 文件 | 根与编译产物只读，可写临时空间有界；每个用例重新创建 |
| CPU/内存/PID | 使用 Linux cgroup 约束，并读取相应指标和事件 |
| 输出与时间 | 有界消费 stdout/stderr、限制输入写入和总期限 |
| 进程后代 | 监督器按期限清理 PID namespace 中的用户后代 |

内存指标是整个用例 cgroup 的观测值，包含 JVM、监督器和后代，不等于 Java 堆大小。具体配置见[隔离运行说明](../../contest/isolated-sandbox.md)。

## 5. 为什么还要持久登记

HTTP 断开和数据库租约过期，都不能证明旧代码已停止。registry 在物理创建前写入 token、内容摘要、slot 和期限；同 token 同内容可在有限保留窗口内回放，异内容拒绝。

只有确认物理对象删除后才释放 slot。删除失败进入 `REAP_PENDING`；管理器退出后，由后继管理器扫描登记并回收残留。没有管理器存活时，容器监督器仍限制代码运行期限。

共享容量依赖同一 daemon 和同一持久本地目录。文件锁通道在 JVM 内按文件共享，不能通过随意关闭另一个通道或删除锁文件来“重置”运行中的锁。

## 6. 什么时候读 native

想理解 stdin、双流读取、进程等待和超时时，再读 [JavaNativeCodeSandbox](../../../codeoj-backend/codeoj-backend-codesandbox/src/main/java/com/codeoj/codeojbackendcodesandbox/service/impl/JavaNativeCodeSandbox.java) 与 [BoundedProcessRunner](../../../codeoj-backend/codeoj-backend-codesandbox/src/main/java/com/codeoj/codeojbackendcodesandbox/service/impl/BoundedProcessRunner.java)。

native 已有有界 I/O、时间预算和资源观测，但不提供 isolated 模式的 Linux 容器边界。资源指标以实际观测结果为准，native 样例只运行可信代码。

## 7. 自测

解释三种情形：无输出死循环、stdout/stderr 持续输出、管理器被杀。每种都指出谁执行期限、谁保存结果、谁回收、何时释放 slot。

通过标准：区分用户错误与平台错误，区分数据库 token 与物理运行，能定位一个真实清理检查。对应测试为 `JavaNativeCodeSandboxTest`、`DurableExecutionRegistryTest`；真实隔离入口为 [check-isolation.py](../../../scripts/local/check-isolation.py)。运行结论查[项目状态](../../status.md)，不在本篇重复计数。
