# 02 模块导读：把完整流程拆开读懂

先完成[项目总览](../01-总览.md)和[一次提交的完整跟读](../03-链路.md#1-一次提交如何受理)，再按下表展开。每篇解释业务背景、调用顺序、关键数据、设计原因，并提供练习及核对要点。

| 建议顺序 | 文档 | 这一篇解决的疑问 |
| --- | --- | --- |
| 1 | [前端与 API](01-前端.md) | 点按钮后发出什么请求？重试与查询结果怎么做？ |
| 2 | [公共层与用户服务](02-公共层与用户服务.md) | 登录后其他服务怎么认识我？角色被修改后怎么办？ |
| 3 | [网关与题目服务](03-网关与题目服务.md) | 题目与提交如何保存？一个受理事务为什么写多张表？ |
| 4 | [判题服务与消息队列](04-判题服务与消息队列.md) | MQ 怎样驱动任务？谁决定执行权？答案在哪比较？ |
| 5 | [代码沙箱](05-代码沙箱.md) | 用户程序怎么编译运行？容器、超时和清理如何配合？ |
| 6 | [赛事与报名](07-赛事与报名.md) | 比赛和普通题库有什么关系？当前报名相比常见秒杀增加了什么？ |
| 7 | [榜单与结算](08-榜单与结算.md) | 迟到 AC 怎样计分？为什么需要重建及最终结算？ |
| 8 | [运行与验证](06-部署与运行.md) | 怎样选择入口、查看状态、理解测试能证明什么？ |

阅读一个方法时，先找调用者，再读正常路径，最后追异常分支。每读完一篇，关闭源码完成练习；不会时按核对要点回查。跨模块的故障场景在[链路篇](../03-链路.md)，口头回答在[面试篇](../04-面试.md)。

代码链接指向当前仓库文件，方法名用于文件内定位。示意代码会明确标注，不替代完整源码；测试链接用于读断言，不表示本次文档改写重新运行了测试。
