# 前端：提交请求和展示状态

**阅读目标：** 读完应能沿页面找到实际请求，并解释报名、提交和轮询分别更新什么状态。

前端使用 Vue 3、TypeScript、Arco Design 和 Monaco。它负责发送请求、保存待确认操作并展示后端状态。

## 1. 从页面找到接口

| 阅读顺序 | 源码 | 重点 |
| --- | --- | --- |
| 页面入口 | [routes.ts](../../../codeoj-frontend/src/router/routes.ts) | 路径、页面组件、access 元信息 |
| 路由权限 | [access/index.ts](../../../codeoj-frontend/src/access/index.ts) | 加载用户；未登录和权限不足分别跳转 |
| 登录状态 | [store/user.ts](../../../codeoj-frontend/src/store/user.ts) | 当前页面使用的登录用户 |
| 通用生成客户端 | [generated/core/request.ts](../../../codeoj-frontend/generated/core/request.ts) | URL、请求头、Cookie 与响应处理 |
| 赛事请求封装 | [api/contest.ts](../../../codeoj-frontend/src/api/contest.ts) | Idempotency-Key、状态类型、稳定 key 与错误提示 |

路由守卫和隐藏按钮只改善交互；管理员权限、提交隐私和参赛资格仍由后端检查。

## 2. 报名与比赛提交

读 [ContestDetailView.vue](../../../codeoj-frontend/src/views/contest/ContestDetailView.vue) 中的 `load → register → submit/sendPending → poll`。

- `load` 分别取得比赛详情和本人报名状态。
- `register` 用稳定 key 报名；返回 PROCESSING 时显示确认中，不显示已有资格。
- `submit` 保存本次待确认请求，`sendPending` 重发原代码和原 key；未确认期间不把新编辑内容当作同一次请求。
- `poll` 查询提交结果。当前详情页只要保留 `lastId` 就会继续轮询，阅读时注意它尚未在终态自动停止。

`stableKey` 在内存和 sessionStorage 中保留请求标识；提交源码只保留在页面内存，不写入该存储。刷新页面后不能依靠 key 自动恢复已丢失的待提交源码。

[ContestsView.vue](../../../codeoj-frontend/src/views/contest/ContestsView.vue) 与详情页显示“已确认人数 / 总名额”，人数取 `capacity - remainingCapacity`。Redis 预留中的请求尚未确认，不能把数据库余量称为当前可抢名额。

## 3. 管理与榜单

- [ManageContestsView.vue](../../../codeoj-frontend/src/views/contest/ManageContestsView.vue)：编辑草稿、发布、取消及资格数据开关。
- [RegistrationOperations.vue](../../../codeoj-frontend/src/components/RegistrationOperations.vue)：带版本和原因执行对账、继续确认或终止请求。
- [ScoreboardPanel.vue](../../../codeoj-frontend/src/components/ScoreboardPanel.vue)：读取榜单和版本元数据；计分由后端完成。

普通练习入口是 [ViewQuestionView.vue](../../../codeoj-frontend/src/views/question/ViewQuestionView.vue)，可与比赛提交对照阅读。

## 4. API 地址与构建

[OpenAPI.ts](../../../codeoj-frontend/generated/core/OpenAPI.ts) 的默认地址为本机 Gateway，启动脚本会配置同源代理。检查地址时同时看 `VUE_APP_API_BASE_URL` 和实际启动端口，不只改页面 URL。

`generated/` 已被页面引用。重新生成时先输出到临时目录，核对实际接口文档地址和差异；不要直接覆盖整个目录。独立构建及完整启动见[前端 README](../../../codeoj-frontend/README.md)。

## 5. 自测

1. 提交响应丢失后继续编辑代码，再点重试，应该重发哪份代码和哪个 key？
2. 页面显示“已确认 0 / 1”，为什么下一位用户仍可能报名失败？

通过标准：在 `submit/sendPending` 找到原请求的保存与重发；分清已确认人数、在途预留和可用库存。
