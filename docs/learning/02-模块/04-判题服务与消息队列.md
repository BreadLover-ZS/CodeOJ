# 判题服务与消息队列：从事件到执行

**阅读目标：** 读完应能解释事件内容、领取响应、执行结果和 ACK 之间的关系。

判题服务不保存权威业务状态。它消费派发事件，经 Feign 领取任务、续租和写回结果；题目服务负责数据库事务。

## 1. 当前使用哪条链

```text
OutboxRelay → RabbitMQ → ReliableJudgeConsumer → ReliableJudgeWorker
          → claim → 调用沙箱/周期 heartbeat → complete 或 fail → ACK
```

旧 `code_exchange/code_queue` 与 `MyMessageConsumer → JudgeServiceImpl` 为兼容分支。当前可靠判题使用独立拓扑，不要混用旧消息体、状态和新 worker。

阅读入口：[OutboxRelay](../../../codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/submission/outbox/OutboxRelay.java)、[ReliableJudgeTopology](../../../codeoj-backend/codeoj-backend-judge-service/src/main/java/com/codeoj/codeojbackendjudgeservice/rabbitmq/ReliableJudgeTopology.java)、[ReliableJudgeConsumer.receive](../../../codeoj-backend/codeoj-backend-judge-service/src/main/java/com/codeoj/codeojbackendjudgeservice/rabbitmq/ReliableJudgeConsumer.java)。

消息模型是 [JudgeDispatch](../../../codeoj-backend/codeoj-backend-model/src/main/java/com/codeoj/codeojbackendmodel/model/reliability/JudgeDispatch.java)：提交 ID、事件、派发代次和协议版本等，不放源码和隐藏用例。领取成功后，内部响应 [JudgeLease](../../../codeoj-backend/codeoj-backend-model/src/main/java/com/codeoj/codeojbackendmodel/model/reliability/JudgeLease.java) 才携带代码、固定规格和执行身份。

## 2. worker 的执行顺序

读 [ReliableJudgeWorker.process](../../../codeoj-backend/codeoj-backend-judge-service/src/main/java/com/codeoj/codeojbackendjudgeservice/judge/ReliableJudgeWorker.java)：

1. 先尝试占本地 slot；没有容量就请求持久延后，不把等待资源算作用户 TLE。
2. `claimExecution` 在题目服务领取执行权。没有领到，说明已完成、过期、未到期或已有有效 owner 等，不直接执行。
3. 领取后周期续租，把固定规格、token 和绝对期限交给沙箱。
4. 将沙箱响应映射为用户判定，或调用策略比较输出。
5. 通过 `completeExecution/failExecution` 写回。数据库再次检查身份与期限；最后释放本地 slot。

本地 slot 只限制这个 worker 的并发。数据库 lease 决定执行权，沙箱 registry 决定物理容量，是三个不同层次。

## 3. 状态和结果分开看

```text
QUEUED → RUNNING → COMPLETED
           └─ 平台失败 → RETRY_WAIT → QUEUED
           └─ 恢复预算耗尽 → NEEDS_ATTENTION
```

| 沙箱响应 | 处理 |
| --- | --- |
| EXECUTED | 检查资源与用例输出，再比较 AC/WA |
| CE、RE、TLE、MLE、OUTPUT_LIMIT | 映射明确的用户错误 |
| PLATFORM_ERROR、REJECTED 或无效协议 | 平台失败路径，有限恢复 |

源码：[SandboxResultMapper](../../../codeoj-backend/codeoj-backend-judge-service/src/main/java/com/codeoj/codeojbackendjudgeservice/judge/SandboxResultMapper.java)、[JavaLanguageJudgeStrategy](../../../codeoj-backend/codeoj-backend-judge-service/src/main/java/com/codeoj/codeojbackendjudgeservice/judge/strategy/JavaLanguageJudgeStrategy.java)。COMPLETED 可以对应 WA；旧 status 字段只是兼容显示。

## 4. 消息何时确认

格式错误消息被拒绝并进入配置的隔离队列。`worker.process` 正常返回后 ACK，可能表示已完成、旧消息无须执行，或已持久延后；不能证明持久处理的异常先退避，再要求重投。

发布与消费分别确认：Broker Confirm 不等于任务完成，Consumer ACK 不等于 AC。具体崩溃窗口和身份字段见[链路 3](../03-链路.md#3-消息重复或进程崩溃后如何恢复)。

报名使用独立的 `RegistrationMessaging/RegistrationConsumer`；成绩投影使用 `ScoreboardMessaging/ScoreboardConsumer`。三类事件复用 Outbox 传输机制，但各自有业务状态和幂等依据。
