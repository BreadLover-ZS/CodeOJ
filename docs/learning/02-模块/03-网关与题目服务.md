# 网关与题目服务：路由和业务权威

**阅读目标：** 读完应能定位一次提交的数据库事务，并说明判题服务通过哪些接口领取和写回。

Gateway 转发请求；题目服务保存提交、资格和成绩事实。判题服务经内部接口领取和写回任务，不直接修改这些数据库状态。

## 1. 先看请求如何到达服务

读 [Gateway 路由配置](../../../codeoj-backend/codeoj-backend-gateway/src/main/resources/application.yml) 和 [GlobalAuthFilter.filter](../../../codeoj-backend/codeoj-backend-gateway/src/main/java/com/codeoj/codeojbackendgateway/filter/GlobalAuthFilter.java)。

用户、题目和判题请求按路由转发。配置中的 `lb://服务名` 表示按服务名寻址；当前本机运行使用静态服务发现，不能据此说已经验证真实 Nacos。内部接口还需通过服务自身的鉴权过滤器。

## 3. 持久数据分别表示什么

| 数据 | 用途 |
| --- | --- |
| `question_submit` | 用户提交和兼容显示结果 |
| `judge_spec` | 不可变用例、限制和比较器版本 |
| `submission_execution`、`judge_attempt` | 工作流、派发代次、执行身份与期限 |
| `reliable_outbox`、`publish_attempt` | 待发布事件与每次发送证据 |
| `contest_problem_snapshot` | 已发布的比赛题目快照 |
| `contest_registration_request`、`contest_registration` | 报名请求与最终确认资格 |
| 榜单投影与回执表 | 可重建排名及已处理结果事件 |

定义见 [V001—V005](../../../codeoj-backend/mysql-init/migrations)。不要只看 `question_submit.status` 就推断有没有重试、租约或人工处理。

## 4. 把事务边界读清楚

提交事务保存业务记录和事件，事务外发布 MQ；报名先做 Redis 预留，再以原身份提交数据库事务。数据库事务内部不执行 Redis、MQ、Feign 或沙箱网络调用。

比赛确认、取消与提交用同一比赛锁确定顺序。确认报名还通过 `remainingCapacity > 0` 条件更新和唯一约束防止超额/重复资格。共享账号检查和其他数据锁的顺序以方法注释及源码为准。

按业务跟读见[链路 1、5、6](../03-链路.md)。旧分支与新版开关的区别统一见[总览](../01-总览.md#5-阅读前确认分支)。
