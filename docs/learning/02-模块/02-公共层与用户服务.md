# 公共层与用户服务：身份、权限和调用契约

**阅读目标：** 读完应能画出一次登录后的账号查询，并分别定位业务权限和内部接口鉴权。

先分清三件事：Session 提供登录身份，当前账号决定业务权限，内部密钥保护服务间接口。

## 1. 公共模型解决什么问题

| 模块 | 内容 | 入口 |
| --- | --- | --- |
| common | 响应包装、错误码、异常、权限注解 | [BaseResponse](../../../codeoj-backend/codeoj-backend-common/src/main/java/com/codeoj/codeojbackendcommon/common/BaseResponse.java)、[ErrorCode](../../../codeoj-backend/codeoj-backend-common/src/main/java/com/codeoj/codeojbackendcommon/common/ErrorCode.java) |
| model | 用户/题目模型、判题协议、执行身份和状态 | [执行模型目录](../../../codeoj-backend/codeoj-backend-model/src/main/java/com/codeoj/codeojbackendmodel/model/reliability) |
| service-client | Feign 声明、账号解析、内部鉴权 | [客户端目录](../../../codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient) |

`BaseResponse.code=0` 表示该业务接口成功，失败码按 `ErrorCode` 枚举区分。HTTP 状态与业务错误码分别读取。内部接口是否包装响应，以实际方法返回类型为准。

## 2. 登录之后，为什么还要查询账号

先读 [UserServiceImpl.userLogin/getLoginUser](../../../codeoj-backend/codeoj-backend-user-service/src/main/java/com/codeoj/codeojbackenduserservice/service/impl/UserServiceImpl.java)，再读 [SessionUserResolver.requireLogin/permitNull](../../../codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/auth/SessionUserResolver.java)。

```text
Cookie → Spring Session Redis → Session 中的用户 ID
       → 查询当前账号 → 检查删除/封禁/角色 → 业务接口
```

Session 中保存过的角色可能已过期。管理员被降权后，即使仍持有原 Cookie，也必须按当前账号拒绝管理操作；查询失败不能回退旧角色。会话 Redis 不可用由 [SessionAvailabilityFilter](../../../codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/filter/SessionAvailabilityFilter.java) 处理，不伪装成普通未登录。

注册和密码校验也在 `UserServiceImpl`：新密码使用 BCrypt，历史固定盐 MD5 格式在登录时兼容并尝试升级。不能据此认定全部旧账号已迁移。

## 3. default 方法与 Feign 请求的区别

[UserFeignClient.getLoginUser](../../../codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/service/UserFeignClient.java) 本身是 Java default 方法，在调用方执行；但它把 `this::getById` 交给账号解析器，后者在 Session 身份有效时调用带 HTTP 映射的 Feign 方法刷新账号。

这条路径包含远程账号查询；用户服务本地的解析路径则直接查自己的数据库。

## 4. 两种授权检查

| 检查 | 作用 | 源码 |
| --- | --- | --- |
| `@AuthCheck` 与显式账号校验 | 判断当前用户能否管理或访问业务 | [AuthInterceptor](../../../codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/aop/AuthInterceptor.java)；各事务中的 `requireAccount` |
| `X-Inner-Secret` | 限制 `/inner/` 服务间接口调用 | [FeignInnerAuthConfig](../../../codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/config/FeignInnerAuthConfig.java)、[InnerApiAuthFilter](../../../codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/filter/InnerApiAuthFilter.java) |

网关与服务内部都检查内部请求，防止直连绕过网关。持有内部密钥不等于具有管理员或参赛权限。AOP 注解依赖代理调用，同类自调用不能想当然地认为经过切面。
