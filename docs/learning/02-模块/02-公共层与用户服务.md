# 02 模块 · 公共层与用户服务

> 阅读范围：`codeoj-backend-common`、`codeoj-backend-model`、`codeoj-backend-service-client`、`codeoj-backend-user-service`。先读[总览](../01-总览.md)。

## Part A：公共层（model / common）

微服务里两个被所有服务依赖的模块，负责定"通用语言"。

### A1. 统一响应 [BaseResponse.java](../../../codeoj-backend/codeoj-backend-common/src/main/java/com/codeoj/codeojbackendcommon/common/BaseResponse.java)

```java
public class BaseResponse<T> {
    private int code;      // 状态码（0 成功，1 失败）
    private T data;        // 业务数据
    private String message;// 提示信息
}
```

- 构造/静态工厂：`ResultUtils.success(data)`、`ResultUtils.error(ErrorCode)`。
- 对外业务接口通常以 `BaseResponse` 包装结果；内部 Feign 接口并不都采用这个包装。读一个接口时应看它的实际返回类型。

### A2. 错误码与异常 [ErrorCode.java](../../../codeoj-backend/codeoj-backend-common/src/main/java/com/codeoj/codeojbackendcommon/common/ErrorCode.java) / [BusinessException.java](../../../codeoj-backend/codeoj-backend-common/src/main/java/com/codeoj/codeojbackendcommon/exception/BusinessException.java)

`ErrorCode` 是枚举：`SUCCESS(0)`、`PARAMS_ERROR(40000)`、`NOT_LOGIN_ERROR(40100)`、`NO_AUTH_ERROR(40101)`、`NOT_FOUND_ERROR(40400)`、`SYSTEM_ERROR(50000)` 等。

业务代码遇到"可预期的错误"就 `throw new BusinessException(ErrorCode.XXX, "自定义提示")`，统一由 [GlobalExceptionHandler.java](../../../codeoj-backend/codeoj-backend-common/src/main/java/com/codeoj/codeojbackendcommon/exception/GlobalExceptionHandler.java) 这里的 `@RestControllerAdvice` 捕获，转成 `BaseResponse` 返回，避免把堆栈抛给前端。配套 `ThrowUtils.throwIf(condition, error)` 简化校验。

### A3. 鉴权注解与常量 [AuthCheck.java](../../../codeoj-backend/codeoj-backend-common/src/main/java/com/codeoj/codeojbackendcommon/annotation/AuthCheck.java) / [UserConstant.java](../../../codeoj-backend/codeoj-backend-common/src/main/java/com/codeoj/codeojbackendcommon/constant/UserConstant.java)

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface AuthCheck {
    String mustRole() default "";  // 为空 = 仅需登录；否则需指定角色
}
```

`UserConstant.USER_LOGIN_STATE` 是 Session 中保存登录用户的 key；`ADMIN_ROLE = "admin"`。注解本身不执行校验，实际逻辑见下文 Part B 的 `AuthInterceptor`。

### A4. model 模块：跨服务共享的数据结构

- **实体**（表映射）：`User`、`Question`、`QuestionSubmit`、`Post`。
- **DTO**（请求体）：`QuestionAddRequest`、`QuestionSubmitAddRequest`、`JudgeCase`（单条用例 input/output）、`JudgeConfig`（timeLimit/memoryLimit/stackLimit）。
- **VO**（脱敏返回）：`LoginUserVO`、`UserVO`、`QuestionVO`、`QuestionSubmitVO`。
- **枚举**：
  - `QuestionSubmitStatusEnum`：`WAITING(0) 待判题 → RUNNING(1) 判题中 → SUCCEED(2) 成功 / FAILED(3) 失败`
  - `QuestionSubmitLanguageEnum`：java/cpp/go（`getEnumByValue` 校验语言合法性）
  - `JudgeInfoMessageEnum`：`ACCEPTED / WRONG_ANSWER / TIME_LIMIT_EXCEEDED / MEMORY_LIMIT_EXCEEDED / ...`
  - `UserRoleEnum`：user / admin / ban
- **沙箱模型**：`ExecuteCodeRequest`（code/language/inputList）、`ExecuteCodeResponse`（outputList/judgeInfo/status/message）、`JudgeInfo`（time/memory/message）。

> 理解点：`QuestionSubmit.status`（判题流程状态）≠ `judgeInfo.message`（答案对错）。status=SUCCEED 只是"判题流程走完了"，message 才是 Accepted / WA / TLE。

## Part B：service-client（服务间调用的"基建"）

这个模块同时被多个服务依赖，装了三样东西。

### B1. OpenFeign 客户端声明

[JudgeFeignClient.java](../../../codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/service/JudgeFeignClient.java)、[QuestionFeignClient.java](../../../codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/service/QuestionFeignClient.java)、[UserFeignClient.java](../../../codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/service/UserFeignClient.java)

用 `@FeignClient(name = "codeoj-backend-question-service", path = "/api/question/inner")` 指向目标服务，带 HTTP 映射的方法对应远程接口。例：

```java
@FeignClient(name = "codeoj-backend-question-service", path = "/api/question/inner")
public interface QuestionFeignClient {
    @GetMapping("/get/id")
    Question getQuestionById(@RequestParam("questionId") long questionId);

    @GetMapping("/question_submit/get/id")
    QuestionSubmit getQuestionSubmitById(@RequestParam("questionId") long questionSubmitId);

    @PostMapping("/question_submit/update")
    boolean updateQuestionSubmitById(@RequestBody QuestionSubmit questionSubmit);
}
```

`UserFeignClient#getLoginUser(request)` 和 `isAdmin(user)` 是接口里的 `default` 方法：它们直接处理当前请求/参数，**不是一次 Feign HTTP 调用**。真正的远程方法要沿 `@GetMapping` 等映射继续找服务端的 InnerController。这个区别决定了登录用户读取和判题服务查题目不是同一种边界。

### B2. 内部接口鉴权（/inner/** 的第二道防线）

[InnerApiAuthFilter.java](../../../codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/filter/InnerApiAuthFilter.java) 是一个 `OncePerRequestFilter`：凡是路径含 `/inner/` 的请求，必须携带正确且非空的 `X-Inner-Secret` 请求头，否则 403。

为什么需要它：网关虽然拦截了外网访问 `/inner/**`，但若攻击者绕过网关直连服务端口（如 8103），仍可能白嫖内部接口。所以各业务服务内部再验一次头，形成**双层防护**。

对应地，[FeignInnerAuthConfig.java](../../../codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/config/FeignInnerAuthConfig.java) 给 Feign 请求自动加上 `X-Inner-Secret` 头——这样服务间调用才能通过对方内部接口的校验。

### B3. 权限切面 [AuthInterceptor.java](../../../codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/aop/AuthInterceptor.java)

```java
@Aspect
@Component
public class AuthInterceptor {
    @Around("@annotation(authCheck)")
    public Object doInterceptor(ProceedingJoinPoint joinPoint, AuthCheck authCheck) throws Throwable {
        // 从当前请求的 session 取登录用户（Spring Session Redis 保证各服务共享同一 session）
        // mustRole 为空：要求已登录且非封号；否则要求角色完全匹配
    }
}
```

- 依赖并扫描到该切面的服务，调用被 `@AuthCheck` 标记的代理方法时才会进入它；具体权限仍要核对 Controller/Service 上的注解。
- 思路：登录态 = Redis Session 里的 `User` 对象；切面读 session → 校验角色 → 放行/抛 `NOT_LOGIN_ERROR`/`NO_AUTH_ERROR`。
- **坑**：AOP 只拦代理调用，同类内 `this.xxx()` 自调用会绕过拦截，跨类注入调用才有效。

## Part C：用户服务（user-service）

### C1. 注册 [UserServiceImpl#userRegister](../../../codeoj-backend/codeoj-backend-user-service/src/main/java/com/codeoj/codeojbackenduserservice/service/impl/UserServiceImpl.java)

流程：参数校验（账号 ≥4 位、密码 ≥8 位、两次一致）→ 按账号查重（`synchronized(userAccount.intern())` 只在当前进程内协调）→ BCrypt 编码新密码 → 插入用户。查重加进程锁不能代替数据库唯一约束或跨实例并发验证。

### C2. 登录 [UserServiceImpl#userLogin](../../../codeoj-backend/codeoj-backend-user-service/src/main/java/com/codeoj/codeojbackenduserservice/service/impl/UserServiceImpl.java)

流程：参数校验 → 按账号查用户 → `checkPassword` 校验密码 → 登录成功时调用 `upgradePasswordIfNeeded` → 把 `User` 放进 Session → 返回脱敏的 `LoginUserVO`。当前源码兼容历史固定盐 MD5 哈希与新 BCrypt 格式，并在登录时尝试升级旧密码；不要把“新注册用 BCrypt”误读成库中所有旧账号都已迁移。

登录态原理：依赖 Spring Session + Redis，session 数据存在 Redis。登录成功后，**题目服务/判题服务处理的请求如果带着同一个 session（JSESSIONID cookie），也能从 Redis 反序列化出同一个 User**，这就是各服务都能"拿到当前登录用户"的原因。

### C3. 内部接口 [UserInnerController.java](../../../codeoj-backend/codeoj-backend-user-service/src/main/java/com/codeoj/codeojbackenduserservice/controller/inner/UserInnerController.java)

提供按 ID 查询用户等内部 HTTP 接口，供其他服务调用。`getLoginUser(HttpServletRequest)`、`isAdmin(User)` 则是上文提到的 `UserFeignClient` 本地 `default` 方法，不能画成一次远程调用。

### C4. 对外 Controller [UserController.java](../../../codeoj-backend/codeoj-backend-user-service/src/main/java/com/codeoj/codeojbackenduserservice/controller/UserController.java)

`/get/login`（获取当前登录用户）、`/login`、`/logout`、`/register`、用户管理接口（部分标 `@AuthCheck(mustRole = ADMIN_ROLE)`）。
