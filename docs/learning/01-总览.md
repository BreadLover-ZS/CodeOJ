# 01 总览 · CodeOJ 学习路线

当前学习主线覆盖 `bc35142` 的可靠判题、赛事报名/榜单及隔离执行器，并补充 2026-10-22 的报名序号约束、Lua 中断恢复及 10000 条账本限制。先读本篇，再按[链路篇](03-链路.md)逐条追源码，最后用[面试篇](04-面试.md)练习表达。复现与证据入口统一在[运行演示交接](../contest/handoff.md)。

## 1. 项目地图

| 组件 | 核心职责 | 入口 |
| --- | --- | --- |
| Vue 前端 | 注册登录、练习提交、比赛管理/参赛、榜单 | codeoj-frontend/src/views/ |
| Gateway | /api 路由、CORS、内部接口访问边界 | GlobalAuthFilter、路由配置 |
| 用户/共享鉴权 | 账号、Spring Session、当前角色刷新 | UserServiceImpl、SessionUserResolver、AuthInterceptor |
| 题目服务 | 提交受理与规格、Outbox、执行权威、赛事报名/计分 | SubmissionAcceptance、ExecutionCommands、RegistrationService、ScoreboardTransactions |
| 判题服务 | 消息消费、领取/续租、远程沙箱、结果映射 | ReliableJudgeConsumer、ReliableJudgeWorker、SandboxResultMapper |
| 沙箱 | 按 attempt/用例隔离、持久 token/slot、回收 | JavaIsolatedCodeSandbox、DurableExecutionRegistry、DockerIsolationEngine、supervisor.py |
| common/model/service-client | 异常、契约、Feign、内部鉴权 | ExecuteCodeRequest/Response、JudgeDispatch/Lease、QuestionFeignClient |

MySQL 是执行、资格与计分事实的权威；RabbitMQ 传递事件，Redis 承载会话/报名预留/榜单缓存，不代替 MySQL 业务完成。Nacos 配置保留，但当前本机证据使用静态服务发现，不算 Nacos 验收。

## 2. 一次可靠提交

```text
前端/Gateway → 题目服务受理事务：提交 + 固定 judgeSpec + execution + Outbox
                    ↓ 事务外发布/确认
                 RabbitMQ
                    ↓ 消费
判题服务 → Feign claim/heartbeat → 远程隔离沙箱 → 结果映射
                    ↓ complete/fail 权威事务
执行结果 + 结果事件 → 计分投影/榜单；消费者处理持久结果后确认本次投递
```

请求键用于业务重试，代次/事件用于派发，attempt/token 用于执行。COMPLETED 是流程状态，AC/WA 等是用户 verdict；平台错误走有限恢复。数据库租约和物理容器回收是两个边界。

## 3. 按什么顺序读

1. [链路一、二](03-链路.md)：受理、固定规格、三层结果语义。先解释正常路径和幂等响应。

3. [链路五、六](03-链路.md)：报名预留/确认/对账、乱序计分/版本/结算；用手工小样例核算。

## 4. 分支与完成标准

三个业务开关 RELIABLE_JUDGE_ENABLED、ASYNC_REGISTRATION_ENABLED、SCOREBOARD_ENABLED 默认关闭；学习新版必须知道迁移和启用条件。沙箱默认 isolated，旧版无 token/deadline 链路只适用于显式可信 native 演示，不能把不同模式的路径拼成一个默认可运行流程。

`bc35142` 有历史完整本机 JV 矩阵、真实依赖和浏览器证据；本次报名恢复修复另有 [248 项后端测试和真实 MySQL/Redis/MQ 故障验证](../../outputs/validation/registration-fix-20261022/report.md)，未重新执行整套 JV、浏览器或容器探针。源码、H2 测试、真实联调、隔离探针属于不同证据层。部署、Nacos、压测继续后置。

报名学习还要掌握 [V005 迁移](../../codeoj-backend/mysql-init/migrations/V005__registration_recovery_fence.sql)：数据库保存预留序号，旧 Redis 账本先关闸核对再升级。比赛容量和累计报名账本均限 10000；释放后的原身份仍计入累计数。

阅读完成应能脱稿画出主链，解释提交后未发布、并发领取、worker 被杀、结果提交后未 ACK 四个窗口；选一个报名未知或榜单乱序场景解释恢复，最后定位源码及运行证据。能背术语但不能解释事实和身份，不算完成。
