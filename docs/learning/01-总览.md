# 01 总览 · CodeOJ 学习路线

这套文档按 **总览 → 模块 → 链路 → 面试** 阅读。目标是先知道每块代码负责什么，再解释一次提交如何跨模块完成，最后把源码事实整理成可追问的面试回答。本文基于当前仓库的静态源码；运行、故障注入和压测结论需要另行验证。

## 1. 项目地图

CodeOJ 是前后端分离的在线判题项目。前端负责展示题目、编辑与提交代码、查看记录；后端由 Gateway、用户服务、题目服务、判题服务和独立代码沙箱组成。

| 组件 | 核心职责 | 第一处入口 |
| --- | --- | --- |
| 前端 | 题目页、编辑器、提交记录与轮询 | `codeoj-frontend/src/views/question/` |
| Gateway | 按 `/api/**` 路由、CORS、拦截内部接口 | `GlobalAuthFilter` 与路由配置 |
| 用户服务 | 注册、登录、Session、用户管理 | `UserController`、`UserServiceImpl` |
| 题目服务 | 题目与提交记录、发判题消息、提供内部读写接口 | `QuestionController`、`QuestionSubmitServiceImpl` |
| 判题服务 | 消费消息、调沙箱、按策略生成结果并回写 | `MyMessageConsumer`、`JudgeServiceImpl` |
| 代码沙箱 | 编译与运行 Java 用户代码 | `ExecuteCodeController`、`JavaNativeCodeSandbox` |
| common / model / service-client | 响应与异常、共享模型、Feign 与鉴权组件 | `BaseResponse`、`QuestionSubmit`、`QuestionFeignClient` |

MySQL 保存业务数据；Redis 与 Spring Session 承载登录态；RabbitMQ 传递待判题的提交 ID；Nacos 用于服务发现。它们支撑模块协作，不负责代替业务状态和恢复逻辑。

## 2. 一次提交的最短路线

```text
做题页 → Gateway → Question Service：保存 QuestionSubmit(WAITING)
                       ↓ 发送 submissionId
                    RabbitMQ
                       ↓ 消费
Judge Service：读取提交和题目 → RUNNING → 调用沙箱 → 判题策略 → 回写结果
                       ↓
提交记录页：按状态查询；有待判题记录时定时刷新
```

提交接口返回提交 ID；结果随后通过提交记录接口查询。消息只携带 ID，消费者还要通过题目服务的内部接口读取题目和用例。正常完成时 `QuestionSubmit.status=SUCCEED` 表示流程结束，是否答对要看 `JudgeInfo.message`；沙箱 `ExecuteCodeResponse.status` 又是另一层状态。当前失败分支不总能把用户代码错误稳定映射为业务 verdict，详见[链路篇](03-链路.md)。

## 3. 四阶段阅读顺序

### 01 总览

先认清模块与数据流，能说出“谁写提交记录、谁发消息、谁执行代码、谁写结果”。不需要先通读所有 DTO、Mapper 或配置。

### 02 模块：先在单个模块内找职责

建议按下列顺序阅读。每篇正文讲职责、关键类、实际行为与边界；篇末只留 3～4 道关键问题，答案应能定位到源码。

1. [公共层与用户服务](02-模块/02-公共层与用户服务.md)：共享模型、Session、权限、内部调用。
2. [网关与题目服务](02-模块/03-网关与题目服务.md)：入口路由、题目数据、提交入库与发消息。
3. [判题服务与消息队列](02-模块/04-判题服务与消息队列.md)：消费确认、编排、策略与结果回写。
4. [代码沙箱](02-模块/05-代码沙箱.md)：远程调用、Java 编译运行与安全边界。
5. [前端](02-模块/01-前端.md)：页面如何发起提交、获取登录态和展示异步结果。
6. [部署与运行](02-模块/06-部署与运行.md)：数据表、配置、Compose 拓扑和启动前检查。

前端或部署也可提前浏览；进入链路篇前，应至少读完中间四个后端模块。

### 03 链路：跨模块解释“为什么会这样”

[链路篇](03-链路.md)按业务问题给出有序源码入口与闭卷成果测试：Java 提交判题、三层状态、MQ 丢失与重复、Java 沙箱安全，鉴权链路可选读。这里重点画“数据库状态—消息状态—进程动作”的时间线，而不是重复介绍每个类。

### 04 面试：把理解转成可核查的回答

[面试篇](04-面试.md)先自己作答，再看“参考回答—源码依据—继续追问—回答边界”。将当前实现、静态审计发现、二开设计和已验证结果分开说；Outbox、CAS、租约、DLQ 等仍是待实现方向时，不说成已有能力。

## 4. 阅读完成的标准

不看文档，能画出一次提交的正常时序，指出两个跨服务边界和一个消息边界；再从“发消息前崩溃、并发重复消费、RUNNING 后崩溃、写回后 ACK 前崩溃”任选其一，说明当前代码可能留下什么状态。最后能定位证据，并说清哪些结论只来自静态阅读。

项目启动和复现条件见仓库 [README](../../README.md)。学习文档不替代可运行环境的验证记录。
