# 01 总览：先理解项目，再读源码

本文按当前已提交版本 `aab471c` 整理。实现与验收范围见[项目状态](../status.md)，启动步骤见[本机运行](../contest/local-startup.md)。

## 1. 项目解决什么问题

CodeOJ 是 Java 在线判题与赛事平台。用户提交代码，平台异步执行并返回判定；比赛还包含限额报名、资格检查、计分和最终结算。

二次开发主要解决四个问题：提交后任务丢失或重复执行、执行失败后无法恢复、报名预留与最终资格不一致、乱序结果导致榜单错误。

## 2. 先记住各部分的职责

| 组件 | 负责什么 | 继续阅读 |
| --- | --- | --- |
| 前端 | 登录、代码编辑、报名和结果展示 | [前端](02-模块/01-前端.md) |
| 用户服务与公共层 | 当前账号、共享会话、业务权限和接口契约 | [用户与鉴权](02-模块/02-公共层与用户服务.md) |
| Gateway | 转发请求、限制内部接口访问 | [网关与题目服务](02-模块/03-网关与题目服务.md) |
| 题目服务 | 受理提交、保存执行状态、确认报名、计分 | 同上 |
| 判题服务 | 消费消息、领取任务、调用沙箱、提交结果 | [判题与消息](02-模块/04-判题服务与消息队列.md) |
| 沙箱 | 编译和运行 Java、限制资源、回收执行对象 | [代码沙箱](02-模块/05-代码沙箱.md) |

MySQL 保存执行、资格和成绩事实；RabbitMQ 传递事件；Redis 保存会话、报名预留和榜单缓存。**返回提交 ID 只代表受理，Redis 预留成功也只代表占到名额，最终结果要查数据库业务状态。**

## 3. 两条主链

```text
提交代码 → 提交/规格/执行记录/Outbox 同事务落库 → MQ
       → 领取执行权 → 沙箱编译运行 → 校验身份后写结果 → 更新榜单

报名 → Redis 原子预留 → 请求/Outbox 同事务落库 → MQ
     → MySQL 确认资格 → 同步 Redis 标记；异常由补建、回收和对账处理
```

## 4. 推荐阅读顺序

跟读每条链路时，记录四件事：入口方法、事务里保存的事实、异步事件、失败后的恢复者。读完后关闭文档画一次时序，再用对应测试核对。


1. 阅读[链路 1—2](03-链路.md#1-一次提交如何受理)：提交受理、状态与结果，先把正常流程讲清。
2. 阅读[链路 3—4](03-链路.md#3-消息重复或进程崩溃后如何恢复)：消息、租约和沙箱，解释任务为什么可以恢复。
3. 阅读[链路 5—6](03-链路.md#5-秒杀报名如何从预留变成资格)：报名与榜单，手算一次竞争和乱序结果。
4. 阅读[链路 7](03-链路.md#7-旧-cookie-为什么不能保留旧权限)：会话、当前权限与内部调用。
5. 完成各节自测，再用[面试篇](04-面试.md)练习表达。模块篇用于查职责和字段，不必从头背完。

第一遍跳过论坛、普通 CRUD 的重复代码、全部 DTO 字段和旧 Compose 细节。需要运行时再读[运行配置](02-模块/06-部署与运行.md)。

## 5. 阅读前确认分支

新版主线需启用 `RELIABLE_JUDGE_ENABLED`；异步报名和榜单分别启用 `ASYNC_REGISTRATION_ENABLED`、`SCOREBOARD_ENABLED`，迁移按 V001—V005 应用。完整本机入口会配置这些条件。

旧 `MyMessageProducer → MyMessageConsumer → JudgeServiceImpl` 仍保留，但不是可靠判题主线。沙箱默认 `isolated`；`native` 只用于显式可信样例。旧流程见[历史图解](../history/legacy-judge-walkthrough.md)。

学完的标准：能画出主链，指出事务里写了什么，并解释“提交后未发消息”“worker 被杀”“结果写库后未 ACK”三个窗口。能背类名但解释不了恢复依据，还需要回到源码。
