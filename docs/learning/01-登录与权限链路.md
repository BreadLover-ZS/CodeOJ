# 链路一：从登录到一次有权限的业务请求

用户提交代码、报名或管理比赛前，系统先要确定“是谁、当前能做什么”。本链从登录页面开始，走到另一个业务服务根据当前账号检查权限。它为后四条链提供身份，但不替代各自的业务资格检查。

## 全局位置与本次场景

用户 U7 登录，然后去题目服务提交程序；管理员还可能发布比赛。这里同时出现浏览器 Cookie、Redis 会话、用户服务、Feign 与角色检查，先把它们接成一条路。

```text
浏览器登录 → Gateway → 用户服务校验密码 → Session 写 Redis
后续提交请求带 Cookie → 题目服务读取共享 Session → 取得用户 ID
  → 用户服务查询当前账号 → 业务权限检查 → 进入提交或管理流程
```

Cookie 携带会话标识；Session 实际保存过 User 对象；当前角色要再查询。前端 store 只负责页面展示，不是后端授权依据。

| 数据/契约 | 这一链中的用途 |
| --- | --- |
| user 表 | 账号、密码摘要、当前角色与删除状态 |
| Redis Session | 跨业务服务识别原登录身份 |
| 登录/用户 VO | 给页面展示的脱敏结果 |
| UserFeignClient | 非用户服务查询当前账号的 HTTP 契约 |
| AuthCheck / 业务检查 | 当前用户能否执行某项操作 |

## 第一遍：正常流程

### 1. 页面怎样发起登录

源码：[UserLoginView.vue](../../codeoj-frontend/src/views/user/UserLoginView.vue)、[UserController.userLogin](../../codeoj-backend/codeoj-backend-user-service/src/main/java/com/codeoj/codeojbackenduserservice/controller/UserController.java)。

**阅读范围：** 页面 handleSubmit 到 userLoginUsingPost，再读 Controller 的 userLogin；关注表单参数、响应成功后的 store 更新与跳转，不必读样式。

页面把账号和密码交给用户接口。Gateway 按 /api/user 路由到用户服务，Controller 解析 DTO、检查参数，再调用 UserServiceImpl。此时还没有建立登录态，也没有进入题目服务。

若先需要注册，沿 [UserRegisterView.vue](../../codeoj-frontend/src/views/user/UserRegisterView.vue) → [UserServiceImpl.userRegister](../../codeoj-backend/codeoj-backend-user-service/src/main/java/com/codeoj/codeojbackenduserservice/service/impl/UserServiceImpl.java)，重点看账号查重、密码确认、BCrypt 编码、用户保存与默认昵称。注册返回账号 ID，登录才建立会话。账号查重中的 synchronized 作用于当前 JVM，不能据此推断多实例注册的全部并发保证。

### 2. 密码验证后怎样建立会话

源码：[UserServiceImpl.userLogin/checkPassword/upgradePasswordIfNeeded](../../codeoj-backend/codeoj-backend-user-service/src/main/java/com/codeoj/codeojbackenduserservice/service/impl/UserServiceImpl.java)。

**阅读范围：** 先读账号查询与 checkPassword，再读升级旧密码、Session setAttribute 和 getLoginUserVO；先走密码正确分支。

登录按账号查记录，再验证密码；BCrypt 不适合重新编码后按字符串相等直接查密码。新注册使用 BCrypt，历史固定盐 MD5 格式通过兼容分支验证后尝试升级。

密码验证成功后，把用户对象放入 USER_LOGIN_STATE，返回 LoginUserVO。Session 与页面 VO 是两份用途不同的数据：前者供后续请求找身份，后者供页面展示。

**回到全局：** 这次登录请求结束，下一次题目请求才使用刚建立的会话。不是把用户服务的一个本地变量传给题目服务。

### 3. Spring Session 怎样把两次请求接起来

源码：[用户服务配置](../../codeoj-backend/codeoj-backend-user-service/src/main/resources/application.yml)、[题目服务配置](../../codeoj-backend/codeoj-backend-question-service/src/main/resources/application.yml)。

**阅读范围：** 找 spring.session、Redis 地址/编号和 Cookie path，再对照 server.servlet.context-path；无需逐项读所有配置。

会话存储在 Redis，浏览器后续按 Cookie 规则带回会话标识。业务服务要使用相容的会话配置与存储位置，才能还原同一 Session。当前 Cookie path 为 /api；Redis 编号不同会使另一个服务查不到同一会话。

前端 [access/index.ts](../../codeoj-frontend/src/access/index.ts) 的 beforeEach 会在缺少登录信息时调用 [store/user.ts](../../codeoj-frontend/src/store/user.ts) 查询当前登录用户。守卫控制页面跳转；API 请求仍需后端检查。

### 4. 题目服务怎样用会话查当前用户

源码：[UserFeignClient.getLoginUser/getById](../../codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/service/UserFeignClient.java)。

**阅读范围：** 先读 default getLoginUser，把传入的 this::getById 与带 HTTP 映射的 getById 对照，然后进入 SessionUserResolver。

getLoginUser 本地执行，负责委托解析；其中 getById 由 Feign 代理发 HTTP 到用户服务。不要因方法位于 Feign 接口就把 default 方法全部当成远程，也不要因它是 default 就说完全没有远程调用。

源码：[SessionUserResolver.requireLogin/permitNull](../../codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/auth/SessionUserResolver.java)。

**阅读范围：** 从 request.getSession(false) 读起，跟到取 ID、lookup 查询、当前账号检查与返回；暂时略过失败分支。

解析器不在缺少会话时创建一个空 Session 冒充登录。它从 Session User 取 ID，再调用 lookup 查询当前账号，返回当前 User。UserServiceImpl 本地调用同一解析器时传 this::getById，本服务数据库查询即可；题目服务通过 UserFeignClient 查询则跨 HTTP。

**到此的数据变化：** Cookie → 会话对象 → 用户 ID → 当前账号。旧 Session 里的角色并不是最终返回的权限事实。

### 5. 当前账号怎样变成业务权限

源码：[AuthInterceptor.doInterceptor](../../codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/aop/AuthInterceptor.java)。

**阅读范围：** 读 AuthCheck 的 mustRole、当前用户获取、角色比较和 proceed，再找实际 Controller 上使用该注解的位置。

没有指定角色的注解要求登录，指定 mustRole 则比较当前角色。管理接口可以使用 AOP，题目删除等还显式检查本人或管理员。不是所有权限都由一个切面统一完成。

源码：[ExecutionRepository.requireAccount](../../codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/submission/ExecutionRepository.java)。

**阅读范围：** 关注角色参数、逻辑删除条件和可选 FOR UPDATE；再在 SubmissionAcceptance、ContestTransactions 中定位调用者。

关键写事务再次检查当前数据库账号；有些路径加锁。入口解析和业务落库是不同时间点。参赛资格由比赛事务检查，管理员身份也不能代替“已经确认报名”等业务条件。

### 6. 内部调用还要通过哪层检查

源码：[FeignInnerAuthConfig](../../codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/config/FeignInnerAuthConfig.java) → [InnerApiAuthFilter.doFilterInternal](../../codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/filter/InnerApiAuthFilter.java)；网关对应 [GlobalAuthFilter.filter](../../codeoj-backend/codeoj-backend-gateway/src/main/java/com/codeoj/codeojbackendgateway/filter/GlobalAuthFilter.java)。

**阅读范围：** 找 X-Inner-Secret 的附加、内部路径匹配、非空/相等检查以及拒绝响应。再看正常公开接口如何继续业务鉴权。

Feign 给内部调用附加服务密钥，服务自身检查以防绕过网关直连；Gateway 也检查内部路径。这个凭据证明调用者持有服务密钥，不证明某位用户有管理员或参赛权限。沙箱的 auth 请求头是另一条执行服务协议。

**交接到下一链：** 当前请求已得到账号并通过相关权限检查，题目 Controller 可以把 User 传给受理服务。继续读[提交与判题](02-提交与判题链路.md)。

## 第二遍：身份和权限发生变化时

### 7. 管理员降权后，原 Cookie 还能做管理吗

回到 SessionUserResolver 的 lookup，再读 AuthInterceptor 的角色比较。假设 U7 登录时是 admin，数据库后来改成 user，Cookie 仍可解析出 U7 的 ID，但 lookup 返回当前 user，管理检查应拒绝。

旧 Cookie 还在与旧权限还在不是同一事实。查询异常不能回退 Session 内旧 admin；删除或封禁也要按当前账号状态处理。题目服务写事务里的 requireAccount 是另一层当前检查。

### 8. 会话 Redis 不可用为什么不能当未登录

源码：[SessionAvailabilityFilter.doFilterInternal](../../codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/filter/SessionAvailabilityFilter.java)。

**阅读范围：** 看过滤器顺序、异常识别、响应已提交条件和 503 返回，不必深读所有框架过滤器。

没有会话是身份缺失，Redis 读取/提交失败是基础设施不可用。当前过滤器在满足条件时返回 SESSION_STORE_UNAVAILABLE，保留诊断边界，不能把暂时失败表现成用户被登出。它也不是所有网络异常的万能恢复器。

### 9. 隐藏按钮和内部密钥分别会漏掉什么

前端守卫不阻止直接 API 请求，因此后端仍需授权。内部密钥不识别具体用户，因此仍要校验账号、资格、执行 token 等。AOP 依赖代理入口，同类直接调用不能想当然认为经过切面；已有外层事务是否覆盖则要另行判断。

### 10. 什么可以返回页面

源码：[UserServiceImpl.getLoginUserVO/getUserVO](../../codeoj-backend/codeoj-backend-user-service/src/main/java/com/codeoj/codeojbackenduserservice/service/impl/UserServiceImpl.java)、[QuestionSubmitServiceImpl.getQuestionSubmitVO](../../codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/service/impl/QuestionSubmitServiceImpl.java)。

**阅读范围：** 对照 Entity 与 VO 的字段，再看他人提交代码的脱敏分支。用户密码、隐藏用例和内部执行身份不能因“共享 model”就原样返回。

BaseResponse 包装业务 code/data/message；HTTP 状态另有含义。内部 Feign 有些直接返回对象或 boolean，按实际签名理解，不强行套页面响应格式。

## 阅读成果与测试

1. 画出登录请求与后续题目请求两段时序，标出 Redis 与 Feign。
2. 同一 Cookie 下管理员降权，逐个指出身份从哪来、角色在哪刷新、在哪拒绝。
3. 分别解释缺会话、账号查询失败、Redis 故障、内部密钥错误，不能全部说成未登录。

核对要点：Session 取 ID、lookup 查当前账号、业务权限与内部鉴权分层；题目写入仍有事务内账号检查。
