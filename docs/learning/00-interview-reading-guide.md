# CodeOJ 面试阅读入口

这套材料只服务于一件事：用最少源码，把 CodeOJ 的异步判题主链讲清楚，并能应对 Java 后端面试中的可靠性与安全追问。

当前项目定位是：**基于现有 OJ 项目进行可靠判题与沙箱安全方向的二次开发，目前完成源码审计和方案设计，功能改造与运行证据仍在推进。**

不要把原项目功能说成个人原创，也不要把设计中的 Outbox、CAS、DLQ、租约恢复说成已经落地。

## 1. 只读这三份

1. 本文：确定项目讲法和阅读范围。
2. [关键源码与判题主链](01-key-source-and-judge-chain.md)：只看 10 个关键类/方法。
3. [高频面试问答与证据边界](02-interview-qa-and-evidence.md)：用问题检验是否真的讲得清。

`archive/` 是旧版审计与设计材料，只在需要追查细节时查阅，不属于日常阅读任务。

## 2. 30 分钟速读路线

### 前 5 分钟：背住项目定位

> CodeOJ 是一个基于 Spring Cloud 的在线判题项目。用户提交代码后，Question Service 先保存提交记录，再通过 RabbitMQ 异步触发 Judge Service；判题服务远程调用代码沙箱执行测试用例，最后按策略比对输出并回写结果。我正在基于现有项目做二次开发，重点解决消息可靠性、重复判题、任务恢复和沙箱安全边界问题。

这段话只描述当前源码和正在进行的方向，不声称二开已经完成。

### 中间 15 分钟：只走一次 Java 提交

记住这一条线：

```text
QuestionController
  -> QuestionSubmitServiceImpl：保存 WAITING
  -> MyMessageProducer：发送 submissionId
  -> MyMessageConsumer：手动 ACK
  -> JudgeServiceImpl：WAITING -> RUNNING
  -> RemoteCodeSandbox / ExecuteCodeController
  -> JavaNativeCodeSandbox：编译、逐用例执行
  -> JudgeManager / JavaLanguageJudgeStrategy：比对结果
  -> QuestionSubmit：SUCCEED 或 FAILED
```

阅读下一份文档时，只打开表格列出的类和方法，不顺着 import 扩散。

### 最后 10 分钟：回答八个必问题

1. 为什么引入 RabbitMQ，而不是提交接口同步判题？
2. 数据库保存成功但 MQ 发送失败，会发生什么？
3. 为什么手动 ACK 仍不能保证任务不丢？
4. 同一 submissionId 被重复投递，为什么可能重复执行？
5. CAS 抢占后为什么还需要 RUNNING 租约恢复？
6. 当前 CE、RE、TLE 为什么可能被记成系统 FAILED？
7. 当前 Java 沙箱为什么不能称为生产级安全沙箱？
8. 到目前为止，哪些是原有代码，哪些是你的工作？

答不清时只回到对应问题的源码，不扩大阅读面。

## 3. 两小时完整准备路线

| 时间 | 内容 | 完成标准 |
|---:|---|---|
| 10 分钟 | 本文和项目定位 | 能用 30 秒介绍项目 |
| 45 分钟 | 10 个关键类/方法 | 能画出提交、消息、判题、沙箱、回写链路 |
| 35 分钟 | 六个核心缺陷 | 能说出当前后果、改造方向和验证方式 |
| 25 分钟 | 高频问答 | 不看答案口述一遍 |
| 5 分钟 | 证据边界 | 不把设计说成实现，不把本地测试说成生产效果 |

## 4. 明确跳过的内容

第一轮面试准备不读：

- 前端页面和组件；
- 用户、题目、提交记录的普通 CRUD；
- 通用响应、异常、分页和工具类；
- 所有配置文件的逐项解释；
- 每个 Feign 接口和 DTO 的字段；
- 管理后台、点赞、收藏等旁支业务；
- 完整压测方案和所有候选二开数据表。

只有面试官沿着权限、微服务调用或数据建模继续追问时，才补相应源码。

## 5. 学完的停止条件

满足下面四项就停止继续看源码：

- 能画出一次 Java 提交的调用链；
- 能区分任务状态、沙箱执行状态和 verdict；
- 能解释六个关键缺陷及改造顺序；
- 能准确说明个人工作目前停留在哪个证据等级。

源码不是看得越多越好。面试准备的目标是形成一条可以被连续追问的项目故事。
