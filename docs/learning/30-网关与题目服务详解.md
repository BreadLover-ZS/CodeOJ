## Part A：网关（gateway，:8101）

### A1. 路由配置 [application.yml](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-gateway/src/main/resources/application.yml)

三个路由，前缀匹配后按服务名负载均衡转发：

| 前缀 | 目标服务 |
|---|---|
| `/api/user/**` | `lb://codeoj-backend-user-service`（:8102） |
| `/api/question/**` | `lb://codeoj-backend-question-service`（:8103） |
| `/api/judge/**` | `lb://codeoj-backend-judge-service`（:8104） |

服务注册到 Nacos，网关 `lb://` 走负载均衡，所以是**唯一对外入口**。其它端口只在内网/容器网络内互相访问，不上对外暴露（安全底线）。

### A2. 全局过滤器 [GlobalAuthFilter.java](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-gateway/src/main/java/com/codeoj/codeojbackendgateway/filter/GlobalAuthFilter.java)

`GlobalFilter`（优先级 `getOrder()=0`）在每个请求进入时：

- 匹配 `/**/inner/**`：要求带 `X-Inner-Secret` 且等于配置密钥，否则直接 403（写"无权限"）。
- 其它路径放行（代码里留了 todo：将来用 JWT 做统一认证）。

> 这是 `/inner/**` 的**第一道**防线；服务内部 `InnerApiAuthFilter` 是**第二道**。两边密钥都来自 `codeoj.inner-auth-secret`（环境变量 `INNER_AUTH_SECRET` 可覆盖）。

### A3. CORS 配置 [CorsConfig.java](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-gateway/src/main/java/com/codeoj/codeojbackendgateway/config/CorsConfig.java)

配置 `CORS_ALLOWED_ORIGINS`（默认 `http://localhost:8000,http://localhost:8080`）白名单，且**允许凭证（allowCredentials）**。注意约束：白名单用一个一个域名写清楚，**不能**用 `*` 加 `withCredentials` 混用（浏览器会拒绝）。

## Part B：题目服务（question-service，:8103）

### B1. 题目 CRUD（[QuestionController.java](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/controller/QuestionController.java)）

典型用法：

- `POST /add`：登录用户创建题目。把 `QuestionAddRequest` 拷到实体，`tags` / `judgeCase` / `judgeConfig` 三个对象用 Gson **序列化成 JSON 字符串**存库（见 `question.tags/judgeCase/judgeConfig` 是 text 列）。
- `GET /get`：原始题目（本人或管理员）。
- `GET /get/vo`：**脱敏题目**（不给答案/用例），普通用户做题用这个。
- `POST /list/page/vo`：分页列表（VO），限 `pageSize ≤ 20` 防爬虫。
- `POST /update`、`/delete`：标 `@AuthCheck(mustRole = admin)`（更新仅管理员；删除仅本人或管理员——在代码里判断）。

### B2. 提交题目 —— 核心入口 [doQuestionSubmit](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/controller/QuestionController.java#L304-L314)

```java
@PostMapping("/question_submit/do")
public BaseResponse<Long> doQuestionSubmit(@RequestBody QuestionSubmitAddRequest req, HttpServletRequest request) {
    if (req == null || req.getQuestionId() <= 0) throw new BusinessException(PARAMS_ERROR);
    final User loginUser = userFeignClient.getLoginUser(request);   // 登录校验
    long id = questionSubmitService.doQuestionSubmit(req, loginUser);
    return ResultUtils.success(id);   // 返回提交记录 id，不是判题结果
}
```

### B3. 提交业务逻辑 [QuestionSubmitServiceImpl#doQuestionSubmit](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/service/impl/QuestionSubmitServiceImpl.java)

顺序如下（建议逐行对照源码）：

1. 用 `QuestionSubmitLanguageEnum.getEnumByValue` 校验语言合法。
2. `questionService.getById(questionId)` 确认题目存在。
3. 组装 `QuestionSubmit`：userId、questionId、code、language；初始 `status = WAITING(0)`、`judgeInfo = "{}"`。
4. `this.save(questionSubmit)` 落库，拿到自增 `questionSubmitId`。
5. **发消息**：`myMessageProducer.sendMessage("code_exchange", "my_routingKey", String.valueOf(questionSubmitId))` —— 消息体只有提交 ID。
6. 用 `UpdateWrapper` 累加 `submitNum` 统计（失败只 warning，不影响主流程）。
7. （注释里保留了一段同步 `CompletableFuture` 调 `judgeFeignClient.doJudge` 的旧方案——现在这行被注释，判题走 MQ。）

**为什么消息体只放 id 而不是整个提交/题目数据？**

- 小消息：避免把大段代码和隐藏用例塞进 MQ，减少序列化/存储开销。
- 以库为准：判题服务拿 id 后通过 Feign 从数据库读"当前快照"。
- 代价：判题服务强依赖题目服务和数据库可用性；若消息发出后题目/用例被改，判题用的是最新数据而非提交当时的快照（存在一致性风险，审计向文档有详述）。

### B5. 查询提交记录 & 脱敏 [QuestionSubmitServiceImpl](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/service/impl/QuestionSubmitServiceImpl.java)

`getQueryWrapper` 支持按 language/status/questionId/userId 过滤 + 排序。核心亮点在 `getQuestionSubmitVO`：

```java
// 脱敏：只有本人或管理员能看到自己的代码
if (userId != questionSubmit.getUserId() && !userFeignClient.isAdmin(loginUser)) {
    questionSubmitVO.setCode(null);
}
```

普通用户看他人提交看不到代码（`QuestionSubmitVO.code` 为 null），这是 VO 存在的意义。

### B6. 内部接口 [QuestionInnerController.java](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/controller/inner/QuestionInnerController.java)

供判题服务 Feign 调用（路径 `/api/question/inner/**`）：

- `GET /get/id`：按 id 取题目。
- `GET /question_submit/get/id`：按 id 取提交记录。
- `POST /question_submit/update`：更新提交记录（判题服务用来改 status/judgeInfo）。
- `POST /update/stats`：累加题目统计（submitNumDelta/acceptedNumDelta）。

这些接口被 `InnerApiAuthFilter` 保护（见《20》B2）。
