## Part A：公共层（model / common）

微服务里两个被所有服务依赖的模块，负责定"通用语言"。

### A1. 统一响应 [BaseResponse.java](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-common/src/main/java/com/codeoj/codeojbackendcommon/common/BaseResponse.java)

```java
public class BaseResponse<T> {
    private int code;      // 状态码（0 成功，1 失败）
    private T data;        // 业务数据
    private String message;// 提示信息
}
```

- 构造/静态工厂：`ResultUtils.success(data)`、`ResultUtils.error(ErrorCode)`。
- 约定：**所有 Controller 都返回 BaseResponse**，前端 OpenAPI 客户端才容易解包。

### A2. 错误码与异常 [ErrorCode.java](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-common/src/main/java/com/codeoj/codeojbackendcommon/common/ErrorCode.java) / [BusinessException.java](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-common/src/main/java/com/codeoj/codeojbackendcommon/exception/BusinessException.java)

`ErrorCode` 是枚举：`SUCCESS(0)`、`PARAMS_ERROR(40000)`、`NOT_LOGIN_ERROR(40100)`、`NO_AUTH_ERROR(40101)`、`NOT_FOUND_ERROR(40400)`、`SYSTEM_ERROR(50000)` 等。

业务代码遇到"可预期的错误"就 `throw new BusinessException(ErrorCode.XXX, "自定义提示")`，统一由 [GlobalExceptionHandler.java](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-common/src/main/java/com/codeoj/codeojbackendcommon/exception/GlobalExceptionHandler.java) 这里的 `@RestControllerAdvice` 捕获，转成 `BaseResponse` 返回，避免把堆栈抛给前端。配套 `ThrowUtils.throwIf(condition, error)` 简化校验。

### A3. 鉴权注解与常量 [AuthCheck.java](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-common/src/main/java/com/codeoj/codeojbackendcommon/annotation/AuthCheck.java) / [UserConstant.java](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-common/src/main/java/com/codeoj/codeojbackendcommon/constant/UserConstant.java)

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface AuthCheck {
    String mustRole() default "";  // 为空 = 仅需登录；否则需指定角色
}
```

`UserConstant.USER_LOGIN_STATE` 存 session 的 key；`ADMIN_ROLE = "admin"`。注解本身不做事，真正干活的是 service-client 里的切面（见 Part C）。

### A4. model 模块：跨服务共享的数据结构

- **实体**（表映射）：`User`、`Question`、`QuestionSubmit`、`Post`。
- **DTO**（请求体）：`QuestionAddRequest`、`QuestionSubmitAddRequest`、`JudgeCase`（单条用例 input/output）、`JudgeConfig`（timeLimit/memoryLimit/stackLimit）。
- **VO**（脱敏返回）：`LoginUserVO`、`UserVO`、`QuestionVO`、`QuestionSubmitVO`。
- **枚举**：
  - `QuestionSubmitStatusEnum`：`WAITING(0) 待判题 → RUNNING(1) 判题中 → SUCCEED(2) 成功 / FAILED(3) 失败`
  - `QuestionSubmitLanguageEnum`：java/cpp/go（`getEnumByValue` 校验语言合法性）
  - `JudgeInfoMessageEnum`：`ACCEPTED / WRONG_ANSWER / TIME_LIMIT_EXCEEDED / MEMORY_LIMIT_EXCEEDED / ...`
  - `UserRoleEnum`：user / admin / ban
- **沙箱模型**：`ExecuteCodeRequest`（code/language/inputList）、`ExecuteCodeResponse`（outputList/judgeInfo/status/message）、`JudgeInfo`（time/memory/message）。

> 理解点：`QuestionSubmit.status`（判题流程状态）≠ `judgeInfo.message`（答案对错）。status=SUCCEED 只是"判题流程走完了"，message 才是 Accepted / WA / TLE。

## Part B：service-client（服务间调用的"基建"）

这个模块同时被多个服务依赖，装了三样东西。

### B1. OpenFeign 客户端声明

[JudgeFeignClient.java](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/service/JudgeFeignClient.java)、[QuestionFeignClient.java](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/service/QuestionFeignClient.java)、[UserFeignClient.java](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/service/UserFeignClient.java)

用 `@FeignClient(name = "codeoj-backend-question-service", path = "/api/question/inner")` 指向目标服务，方法签名就是远程 HTTP 接口。例：

```java
@FeignClient(name = "codeoj-backend-question-service", path = "/api/question/inner")
public interface QuestionFeignClient {
    @GetMapping("/get/id")
    Question getQuestionById(@RequestParam("questionId") long questionId);

    @GetMapping("/question_submit/get/id")
    QuestionSubmit getQuestionSubmitById(@RequestParam("questionId") long questionSubmitId);

    @PostMapping("/question_submit/update")
    boolean updateQuestionSubmitById(@RequestBody QuestionSubmit questionSubmit);
}
```

### B2. 内部接口鉴权（/inner/** 的第二道防线）

[InnerApiAuthFilter.java](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/filter/InnerApiAuthFilter.java) 是一个 `OncePerRequestFilter`：凡是路径含 `/inner/` 的请求，必须携带正确且非空的 `X-Inner-Secret` 请求头，否则 403。

为什么需要它：网关虽然拦截了外网访问 `/inner/**`，但若攻击者绕过网关直连服务端口（如 8103），仍可能白嫖内部接口。所以各业务服务内部再验一次头，形成**双层防护**。

对应地，[FeignInnerAuthConfig.java](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/config/FeignInnerAuthConfig.java) 给 Feign 请求自动加上 `X-Inner-Secret` 头——这样服务间调用才能通过对方内部接口的校验。

### B3. 权限切面 [AuthInterceptor.java](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/aop/AuthInterceptor.java)

```java
@Aspect
@Component
public class AuthInterceptor {
    @Around("@annotation(authCheck)")
    public Object doInterceptor(ProceedingJoinPoint joinPoint, AuthCheck authCheck) throws Throwable {
        // 从当前请求的 session 取登录用户（Spring Session Redis 保证各服务共享同一 session）
        // mustRole 为空：要求已登录且非封号；否则要求角色完全匹配
    }
}
```

- 这个切面**属于依赖了 service-client 的任意服务**，所以题目服务、用户服务里凡是标了 `@AuthCheck` 的接口都会走它。
- 思路：登录态 = Redis Session 里的 `User` 对象；切面读 session → 校验角色 → 放行/抛 `NOT_LOGIN_ERROR`/`NO_AUTH_ERROR`。
- **坑**：AOP 只拦代理调用，同类内 `this.xxx()` 自调用会绕过拦截，跨类注入调用才有效。

## Part C：用户服务（user-service）

### C1. 注册 [UserServiceImpl#userRegister](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-user-service/src/main/java/com/codeoj/codeojbackenduserservice/service/impl/UserServiceImpl.java)

流程：参数校验（账号 ≥4 位、密码 ≥8 位、两次一致）→ 按账号查重（用 `synchronized(userAccount.intern())` 缓冲并发注册竞争）→ **BCrypt 加密存储**（一个用户一个随机盐，抵抗彩虹表）→ 插入 + 生成默认昵称。

### C2. 登录 [UserServiceImpl#userLogin](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-user-service/src/main/java/com/codeoj/codeojbackenduserservice/service/impl/UserServiceImpl.java)

流程：参数校验 → 按账号查用户 → `checkPassword` 校验密码（**bcrypt 不存储明文/不可逆，所以先按账号查出再比对**）→ 把 `User` 对象放进 `request.getSession().setAttribute(USER_LOGIN_STATE, user)` → 返回脱敏的 `LoginUserVO`。

登录态原理：依赖 Spring Session + Redis，session 数据存在 Redis。登录成功后，**题目服务/判题服务处理的请求如果带着同一个 session（JSESSIONID cookie），也能从 Redis 反序列化出同一个 User**，这就是各服务都能"拿到当前登录用户"的原因。

### C3. 内部接口 [UserInnerController.java](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-user-service/src/main/java/com/codeoj/codeojbackenduserservice/controller/inner/UserInnerController.java)

对外暴露 `getLoginUser(HttpServletRequest)`、`isAdmin(User)` 等 Feign 接口，供题目服务/判题服务调用。这些都在 `/inner/user/**` 路径下，受 B2 的过滤器保护。

### C4. 对外 Controller [UserController.java](file:///e:/gitStore/ZSOJ/codeoj-backend/codeoj-backend-user-service/src/main/java/com/codeoj/codeojbackenduserservice/controller/UserController.java)

`/get/login`（获取当前登录用户）、`/login`、`/logout`、`/register`、用户管理接口（部分标 `@AuthCheck(mustRole = ADMIN_ROLE)`）。
