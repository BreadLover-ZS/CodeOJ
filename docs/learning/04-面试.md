## 1. 怎样介绍项目

CodeOJ 是基于课程基础版本二次开发的 Java 在线判题与赛事平台。核心工作包括可靠异步判题、执行租约与隔离回收、限额报名和可重建榜单。先讲清其中两三条自己掌握的链路，再展开故障例子。

## 2. 为什么用 Outbox 后还可能重复消息

Outbox 使提交与派发意图同事务保存，解决“提交成功却没有可恢复事件”。发布仍跨越 DB 与 Broker；Broker 接收后确认丢失，重试可能重复发送，因此消费者还要检查业务身份和状态。

源码：[`SubmissionAcceptance.write`](../../codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/submission/SubmissionAcceptance.java)、[`OutboxStore.claim/record`](../../codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/submission/outbox/OutboxStore.java)。

追问：为什么不在数据库事务中直接调用 MQ？

## 3. Confirm、Return、Consumer ACK 有什么区别

Confirm 是发布确认，Return 表示路由失败，Consumer ACK 结束本次投递。它们都不证明 AC；已完成、过期或已持久转入恢复的任务，也可能被 ACK。

源码：[`OutboxDelivery.publish`](../../codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/submission/outbox/OutboxDelivery.java)、[`ReliableJudgeConsumer.receive`](../../codeoj-backend/codeoj-backend-judge-service/src/main/java/com/codeoj/codeojbackendjudgeservice/rabbitmq/ReliableJudgeConsumer.java)。

追问：结果写库后、ACK 前退出，会发生什么？

## 4. 两个消费者为什么不会同时获得有效执行权

领取在数据库行锁内检查状态、派发代次与事件，成功后生成执行 attempt/token。另一个消费者读到变化后的状态，不能重复领取。worker 的本地 Semaphore 只限制本实例并发，不能替代数据库执行权。

源码：[`ExecutionCommands.claim`](../../codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/submission/ExecutionCommands.java)、[`ReliableJudgeWorker.process`](../../codeoj-backend/codeoj-backend-judge-service/src/main/java/com/codeoj/codeojbackendjudgeservice/judge/ReliableJudgeWorker.java)。

追问：把它改成“先查 WAITING，再普通更新”会有什么问题？

## 5. token、代次和租约各解决什么问题

代次和 eventId 区分当前派发；attempt/token 区分当前执行；租约限定执行权有效期。续租和写结果都校验身份与期限，旧 worker 即使算出了正确答案，也不能覆盖新执行。

源码：[`ExecutionCommands.currentMessage/sameToken/owned/recover`](../../codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/submission/ExecutionCommands.java)。

追问：数据库拒绝旧结果后，旧容器是不是已经停止？

## 6. 幂等为什么不能只靠 messageId

用户请求用 requestKey 和内容 hash 防重复受理；执行用 token 和结果摘要防冲突写回；榜单用业务回执防重复投影。它们保护不同操作，一个传输消息 ID 无法代替全部业务约束。

源码：[`SubmissionAcceptance.replay`](../../codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/submission/SubmissionAcceptance.java)、[`ExecutionCommands.complete`](../../codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/submission/ExecutionCommands.java)、[`ScoreboardTransactions.project`](../../codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/scoreboard/ScoreboardTransactions.java)。

追问：同 key 换代码重试为什么要冲突？

## 7. 为什么要区分平台失败与用户错误

WA、CE、RE 等是用户代码的判定；沙箱不可达、协议或必要指标缺失属于平台失败。平台失败应有限恢复，耗尽后进入 NEEDS_ATTENTION，不能记成用户 WA 或无限重试。

源码：[`SandboxResultMapper`](../../codeoj-backend/codeoj-backend-judge-service/src/main/java/com/codeoj/codeojbackendjudgeservice/judge/SandboxResultMapper.java)、[`JavaLanguageJudgeStrategy`](../../codeoj-backend/codeoj-backend-judge-service/src/main/java/com/codeoj/codeojbackendjudgeservice/judge/strategy/JavaLanguageJudgeStrategy.java)、[`ExecutionCommands.fail/manualRetry`](../../codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/submission/ExecutionCommands.java)。

追问：输出正确但内存指标缺失，可以 AC 吗？

## 8. 为什么进程跑在容器中还不够

还要核对用户身份、网络、挂载、资源限制和后代清理。当前 isolated 模式按编译尝试及用例隔离，用户进程非 root、禁网、根与产物只读，CPU/内存/PID 受 cgroup 约束。

源码：[`JavaIsolatedCodeSandbox`](../../codeoj-backend/codeoj-backend-codesandbox/src/main/java/com/codeoj/codeojbackendcodesandbox/service/impl/JavaIsolatedCodeSandbox.java)、[`DockerIsolationEngine`](../../codeoj-backend/codeoj-backend-codesandbox/src/main/java/com/codeoj/codeojbackendcodesandbox/service/impl/DockerIsolationEngine.java)、[`supervisor.py`](../../codeoj-backend/codeoj-backend-codesandbox/isolation/supervisor.py)。

追问：为什么用户 stdout 不能当执行完成的可信收据？

## 9. 管理器被杀后怎样回收资源

容器监督器独立限制期限；管理器提前持久登记 token、slot 和物理对象。后继管理器取得恢复权后清理旧对象，确认删除后才释放 slot。清理失败保留占用，不能只因数据库租约过期就归还容量。

源码：[`DurableExecutionRegistry`](../../codeoj-backend/codeoj-backend-codesandbox/src/main/java/com/codeoj/codeojbackendcodesandbox/service/impl/DurableExecutionRegistry.java)、[`JavaIsolatedCodeSandbox.recoverExecutions`](../../codeoj-backend/codeoj-backend-codesandbox/src/main/java/com/codeoj/codeojbackendcodesandbox/service/impl/JavaIsolatedCodeSandbox.java)。

追问：共享目录、文件锁和同一 Docker daemon 分别起什么作用？

## 10. Redis Lua 成功为什么不等于报名成功

Lua 只完成名额预留。请求和 Outbox 落库后，消费者再由 MySQL 确认资格；PROCESSING 不能当成已参赛。预留与最终确认分开，才能处理数据库和消息异常，同时保留原请求身份。

源码：[`RegistrationService.register`](../../codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/contest/RegistrationService.java)、[`RegistrationTransactions.persist/confirm`](../../codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/contest/RegistrationTransactions.java)。

追问：Redis 成功、DB 落库前进程退出，依据什么恢复？

## 11. Lua 报错为什么不能直接加回库存

脚本原子执行不代表运行时报错会撤销之前的写入。系统先保存 mutation 意图，再更新库存、映射和账本；repair 核验原身份及当前值，写入确定目标值。查询不到映射也不能直接断言没有扣过库存。

源码：[`contest-registration.lua`](../../codeoj-backend/codeoj-backend-question-service/src/main/resources/lua/contest-registration.lua) 的 `apply/repair`、[`RegistrationService.recoverUnknown`](../../codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/contest/RegistrationService.java)。

追问：释放写完库存后报错，怎样避免第二次退款？

## 12. 旧快照和迟到对账分别怎样处理

旧快照可能记录数没变、身份却已丢失，需检查持久序号高水位，并以 V005 唯一约束拦住序号复用。对账还必须固定本次 revision；迟到错误通过 `issueIfCurrent` 校验原 epoch/revision，不能暂停更新的成功恢复。

源码：[V005](../../codeoj-backend/mysql-init/migrations/V005__registration_recovery_fence.sql)、[`RegistrationTransactions.settings/issueIfCurrent`](../../codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/contest/RegistrationTransactions.java)、[`RegistrationService.reconcile`](../../codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/contest/RegistrationService.java)。

追问：为什么只给 Redis 闸门加版本判断仍不够？

## 13. 为什么超时、失败和取消不能同样处理

超时表示结果未知，可能已经确认，不能立即退款。明确失败或取消先写数据库终态，再按原预留身份幂等释放；已确认资格不走普通失败回收，迟到消费者也不能重新确认已终止请求。

源码：[`RegistrationTransactions.review/recover`](../../codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/contest/RegistrationTransactions.java)、[`RegistrationService.synchronize`](../../codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/contest/RegistrationService.java)。

追问：数据库已 RELEASED，Redis 却回到旧 PROCESSING，怎么收敛？

## 14. 结果乱序为什么不影响最终榜单

每题取最早 AC 的提交受理时间，而非消息到达时间。更早 AC 晚到会修正达成时间；回执与投影同事务，零分用户也入榜。重建根据持久事实生成新版本，核对后切换，最终修订保留旧版本。

源码：[`ScoreboardTransactions.project/rebuild/finish`](../../codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/scoreboard/ScoreboardTransactions.java)、[`ScoreboardService.page`](../../codeoj-backend/codeoj-backend-question-service/src/main/java/com/codeoj/codeojbackendquestionservice/scoreboard/ScoreboardService.java)。

追问：并列跨页如何稳定？为什么比赛到点不能直接 FINISHED？

## 15. 撤销管理员后，旧 Cookie 为什么不能继续管理

Session 只提供身份 ID，后端每次重新查询当前账号和角色。`UserFeignClient.getLoginUser` 本地执行，但内部的 `getById` 会远程查询；查询异常不回退 Session 角色。内部调用密钥不代替业务权限。

源码：[`SessionUserResolver`](../../codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/auth/SessionUserResolver.java)、[`UserFeignClient`](../../codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/service/UserFeignClient.java)、[`AuthInterceptor`](../../codeoj-backend/codeoj-backend-service-client/src/main/java/com/codeoj/codeojbackendserviceclient/aop/AuthInterceptor.java)。

追问：会话 Redis 不可用，为什么不能统一当未登录？

- 源码入口可从[模块索引](02-模块/README.md)或[链路篇](03-链路.md)打开；讲个人贡献前要能解释实现和一个失败场景。
- 测试、真实依赖联调和生产验收是不同层次，具体版本与数字只查[项目状态](../status.md)。没有测量就不写 QPS、延迟或可用率。
- 不说“从零原创”“消息或执行恰好一次”“容器就绝对安全”。优先讲机制解决了哪个具体问题，以及还受什么条件限制。
