对应最近完整验收源码基线 `19f77fc`，版本与范围见[项目状态](../status.md)。先完成[源码链路与闭卷测试](03-链路.md)，再按“业务问题 → 实现 → 故障窗口 → 证据/限制”回答。以下是练习口径；讲述个人贡献前，必须自己能定位代码、画时序并解释测试，不能把工具完成的工作直接当成已掌握。

## 1. 项目介绍与贡献

### 1. 用 30 秒介绍项目

**参考回答：** CodeOJ 是基于课程基础版本继续开发的 Java 在线判题和赛事平台。我围绕异步判题可靠性做了事务 Outbox、执行身份与租约恢复，又加入比赛快照、限额报名、可重建榜单，以及逐用例容器隔离和残留执行回收。当前完成固定版本的本机真实依赖与受控故障验收，部署和压测还没做。

**源码依据：** SubmissionAcceptance、ExecutionCommands、JavaIsolatedCodeSandbox、RegistrationService、ScoreboardTransactions；[验收报告](../../outputs/validation/overall-acceptance-20261023/report.md)。

**继续追问：** 哪部分来自课程？最难定位的问题是什么？为什么需要 MQ？

**回答边界：** 不说从零原创、不说生产级或高并发指标；基础微服务架构参考课程，二开重点要能逐项定位。

### 2. 两分钟怎样讲清个人二开

**参考回答：** 基础链路是提交落库后直接发消息，消费时查状态再执行。我的二开先把受理、固定判题规格和派发事件放进一个数据库事务，再通过 Outbox 发布；消费领取由数据库权威状态决定，旧代次和过期执行身份不能回写。平台失败有有限自动恢复和人工处理。物理侧按 attempt 编译、每个用例新容器，限制资源并持久登记，只有物理对象回收后才归还容量。赛事侧以 MySQL 确认资格，Redis 做预留；榜单从提交/结果事实重建，保留最终版本。验证使用独立 MySQL/Redis/MQ、真实浏览器、双 worker/管理器和进程崩溃样例，全部限定于本机范围。

**源码依据：** [源码地图](../contest/source-reading.md)与[逐项矩阵](../../outputs/validation/overall-acceptance-20261023/jv-matrix.md)。

**继续追问：** 选一个崩溃窗口，逐行解释恢复；如果移除 Redis，哪些业务事实还在？

**回答边界：** 不罗列所有技术栈充当贡献；挑自己已读懂的两三个机制展开。

## 2. 可靠判题

### 3. 为什么用了 Outbox 仍可能重复发消息

**参考回答：** 提交和 Outbox 同事务解决“提交成功却没留下派发意图”。发布器在 DB 之外发 Broker，接收成功但确认丢失时不能证明没发出去，后续恢复可能重发。每次 publish_attempt 和 publication token 记录本次发送证据，业务领取还必须幂等。

**源码依据：** SubmissionAcceptance#write、OutboxStore#claim/record、OutboxDelivery#publish。

**继续追问：** 为什么不在 @Transactional 中直接调用 RabbitMQ？超时能不能判失败？

**回答边界：** 不承诺消息恰好投递一次；UNKNOWN 不能当明确未发送。

### 4. Confirm、Return、ACK 分别证明什么

**参考回答：** Confirm 是 Broker 对发布的确认，Return 表示路由问题，Consumer ACK 处理本次投递；它们都不等于用户答案 AC。可靠消费者在任务已完成、消息过期，或者已持久转入重试等情况下也可 ACK；不能证明持久处理的异常退避后重投，格式坏消息进入隔离队列。

**源码依据：** OutboxDelivery、ReliableJudgeTopology、ReliableJudgeConsumer#receive。

**继续追问：** 结果写库后、ACK 前被杀，为什么不会再计一次分？

**回答边界：** 不把 Broker 确认当作业务事务提交。

### 5. 两个消费者如何避免同时取得有效执行权

**参考回答：** claim 在权威执行记录行锁内检查 QUEUED、dispatchGeneration、eventId、到期时间和恢复预算，再生成 attempt/token 并持久化。第二个领取者看到已变化状态就不能领取。不是旧版先查 WAITING 再普通 update 的竞态，也不只是 JVM 内锁。

**源码依据：** ExecutionCommands#claim、ExecutionRepository#find；JV04 的真实双 worker 与精确观察。

**继续追问：** 为什么只加 Redis 锁不够？事务内能否调用沙箱？

**回答边界：** 这是数据库业务执行权；物理执行能否结束还要靠沙箱期限和回收。

### 6. 代次、token、租约为什么不能合成一个状态字段

**参考回答：** dispatchGeneration/eventId 识别当前派发，attemptNo/token 识别当前执行，leaseUntil 约束执行所有权存活，attemptDeadline/recoveryDeadline 限制阶段和整体恢复。heartbeat/complete/fail 检查身份及期限，恢复重派发递增代次。旧 worker 迟到，即使答案正确也不能覆盖新执行结果。

**源码依据：** ExecutionCommands#currentMessage/sameToken/owned/recover、ReliableJudgeWorker#process。

**继续追问：** 旧 worker 已经执行完但租约刚过期怎么办？为什么用数据库时间？

**回答边界：** 拒绝过期结果可能增加一次执行成本；不能牺牲权威身份去接受迟到写回。

### 7. 什么叫业务幂等，为什么不只靠 messageId

**参考回答：** 提交请求用用户维度 requestKey 与内容 hash；同键同内容返回原 ID，变内容冲突。执行用代次/事件与 token；相同完成 token 与结果摘要可回放，冲突结果拒绝。计分还用业务回执与事务保护投影。网络消息 ID 只是传输身份，覆盖不了这些不同操作。

**源码依据：** ReliableSubmissionService、SubmissionAcceptance#replay、ExecutionCommands#complete、ScoreboardTransactions#project。

**继续追问：** 接口提交已成功但响应丢失，前端重试应该换 key 吗？

**回答边界：** 沙箱 token 结果只在有界持久保留窗口中重放，不等于永不清理的全局去重库。

### 8. 为什么需要 NEEDS_ATTENTION

**参考回答：** 自动恢复受最大 attempts、派发数和 recovery deadline 限制。平台失败不应无限占资源，也不能变成用户 WA。耗尽进入 NEEDS_ATTENTION，管理员按 expectedVersion、理由、有限追加预算处理并审计；不是任意改结果或无条件重新跑。

**源码依据：** ExecutionCommands#fail/recover/manualRetry、ExecutionAdminController。

**继续追问：** 重复点击人工重试如何避免叠加预算？业务状态版本起什么作用？

**回答边界：** 业务自动尝试预算和 Broker 传输退避是两层机制，不能声称数据库不可达时所有重投都有限次完成。

## 3. 沙箱与真实故障

### 9. 为什么“容器里运行”还不等于完整隔离

**参考回答：** 要检查具体挂载、身份、网络和资源边界。这里用户 Java UID/GID10000、capabilities 清空、无网络、只读根和产物、有限 tmpfs；不挂宿主业务目录或 socket；CPU/内存/PID 由 cgroup 约束。每个用例用新容器和私有收据，不能用用户 stdout 作为控制协议。

**源码依据：** JavaIsolatedCodeSandbox、DockerIsolationEngine、supervisor.py；JV08 的真实越界样例。

**继续追问：** 为什么监督器保留容器内 root？它和用户代码怎样区分？

**回答边界：** 监督器仅保留降权与清理所需能力；本机受控验证不等于内核逃逸认证或可直接开放恶意代码服务。

### 10. 管理器被杀之后，谁停止用户代码

**参考回答：** 容器内受信监督器独立于 HTTP 和 JVM 管理器，按阶段预算/绝对期限杀掉 namespace 中的后代。持久 token/slot journal 先于物理创建写入；新管理器取得恢复权后清理旧容器/卷并记录 OWNER_LOST。未确认清理时 slot 不能释放，删除失败保留 REAP_PENDING。

**源码依据：** DurableExecutionRegistry、JavaIsolatedCodeSandbox#recoverExecutions、supervisor.py；JV25 双管理器及 SIGKILL 验证。

**继续追问：** 数据库租约过期为什么不能直接归还物理容量？没有任何管理器存活时怎么办？

**回答边界：** 同池必须同 daemon、同持久本地目录、同策略；未验证跨宿主文件锁或状态盘被删。

### 11. 本轮定位过什么难复现的问题

**参考回答：** 真实双 JVM 运行时，竞争者关闭同一文件的另一个 FileChannel，可能释放该 JVM 对文件持有的 POSIX 锁，导致另一管理器误判执行已失去 owner 并回收活跃容器。同 JVM 的替身测试没有暴露这个问题。修复后按文件共享长期打开的通道，只释放 FileLock，并增加独立 JVM 锁观察，再重跑隔离和业务矩阵。

**报名补充案例：** Redis 旧快照只保留尚未落库的 A，而数据库只有已确认的 B，两边各一条记录，旧维护逻辑仍允许 C 预留并先确认，导致 A 转人工。修复增加持久预留序号和唯一约束；即使最大序号的查询结果已经过旧，数据库仍拒绝另一身份复用该序号。这个缺陷没有突破最终容量约束，影响的是预留保障与恢复完整性。

**源码依据：** DurableExecutionRegistry 的通道共享与 Held#close、DurableExecutionRegistryTest；[隔离根因记录](../../outputs/validation/isolation-20261022/report.md)。报名看 RegistrationMaintenance、RegistrationTransactions、V005，以及[审查后修复验证](../../outputs/validation/registration-fix-20261022/report.md)。

**继续追问：** 文件锁和 Java synchronized 分别保护什么？为什么不能运行中删锁文件重置？

**回答边界：** 能说清测试为什么漏掉、后续如何补证；不要只讲“加一把分布式锁”。

### 12. CE、RE、TLE、MLE 与平台错误如何区分

**参考回答：** 明确编译诊断是 CE，正常资源范围内用户 JVM 非零退出是 RE，受信监督器确认超时是 TLE，cgroup OOM 事件是 MLE；双流输出预算溢出是 OUTPUT_LIMIT。引擎、收据、入口和指标异常留在平台错误路径。EXECUTED 再按冻结比较器比较输出，正确才是 AC。

**源码依据：** JavaIsolatedCodeSandbox、SandboxResultMapper、JavaLanguageJudgeStrategy、TextOutputComparator。

**继续追问：** 程序输出正确但内存指标缺失，能不能 AC？native RSS 与 cgroup peak 有什么差异？

**回答边界：** CGROUP_V2_PEAK_KIB 包含监督器、JVM 和后代，不是 Java 堆。native RSS 是采样值，不宣称等同硬隔离；短命进程缺指标不能填 0。

## 4. 报名、榜单与权限

### 13. Redis Lua 成功是不是报名成功

**参考回答：** 只是得到预留，真正资格由 MySQL 确认。Lua 原子检查窗口/身份/容量并写预留；持久化请求与 Outbox 后异步确认。前端看到 PROCESSING 不能当已参赛。预留后崩溃可按原身份补建，未知状态不能立即加库存。Lua 中途报错也不会自动撤销此前写入，所以先记录完整操作意图，再按目标值恢复；查不到用户映射不足以证明没有扣过库存。旧快照通过已落库的预留序号和唯一约束阻止重新分配已知身份位置。

**源码依据：** RegistrationService#register/recoverUnknown/persist、RedisRegistrationLedger#check、Lua anchored/apply/repair、RegistrationTransactions、RegistrationConsumer、V005。

**继续追问：** Redis 成功、DB 写入前被杀怎么恢复？Lua 已扣库存但没写映射就报错怎么办？两侧条数相等为什么仍可能需要暂停？8 人争 2 名额，哪个约束最终防超卖？

**回答边界：** 新代码有操作意图才能修复部分执行；没有意图的历史损坏、Redis 与数据库同时丢失不能靠猜测恢复。10000 是准入/账本保护上限，真实 Lua 边界测试不等于 10000 个完整账号验收或已测得某个 QPS。

### 14. 为什么取消或超时后不能立即释放预留

**参考回答：** 超时可能只是响应未知，后台确认可能已提交。先以 MySQL 终态决定可释放，再携带原 epoch/预留身份让 Lua 幂等归还；确认成功但 Redis 标记失败则补标记。账本丢失或时钟偏差暂停准入并对账，旧确认不能复活已取消资格。

**源码依据：** RegistrationService#synchronize/reconcile、RegistrationTransactions#recover、RegistrationMaintenance。

**继续追问：** 已取消后收到晚到的确认消息，怎么拒绝？释放脚本写完库存后报错，怎样保证不重复归还？数据库已是 RELEASED、Redis 却恢复到旧状态时怎么办？Redis 完全丢账能直接重设库存吗？

**回答边界：** 不把客户端 timeout 当明确未发生，也不把缓存重置当对账。

### 15. 晚到结果如何影响排名，为什么榜单可以重建

**参考回答：** 用冻结结果与 acceptedAt 重算每人每题最早 AC，事件消费时间不参与计分。更早 AC 晚到会调整 achievedAt。去重回执与投影在同一事务，并列名次是严格领先人数+1；零分确认用户也入榜。重建写新 projectionVersion，验证后切换，最终修订保留历史版本。

**源码依据：** ScoreboardTransactions#project/snapshot/rebuild/finish、ScoreboardService#page、ContestLifecycle。

**继续追问：** 并列跨页如何保持稳定？缓存旧页如何避免混入新版本？何时能 FINALIZING → FINISHED？

**回答边界：** 当前比赛锁较粗，未用压测证明榜单吞吐；Redis entries 缓存不承担事实权威。

### 16. 管理员撤权后，旧 Cookie 为什么不应继续生效

**参考回答：** Session 序列化角色会过期，所以只取用户 ID，再查当前账号的角色、删除和封禁状态；查询失败不能回退旧管理员。UserFeignClient 的 default 方法本地执行，但刷新账号会调用有映射的 Feign 查询，不能把整个路径说成无网络。Redis 会话不可用返回 503，也不能伪装为普通未登录。

**源码依据：** SessionUserResolver、UserFeignClient#getLoginUser、AuthInterceptor、SessionAvailabilityFilter；当前 53 项真实权限检查。

**继续追问：** 内部密钥能否替代业务权限？只封 Gateway 内部路径是否足够？

**回答边界：** 区分当前账号权威、网关路由、服务内部鉴权和代码隔离，各自验证。

## 6. 自测方式

每次只选一道题，先脱稿回答，再对照源码补上事务、身份或恢复依据。优先练 3、5、6、10、11、13、15、16；通过标准是能画失败时间线并指出一份实际证据。学习成果测试继续放在链路篇，面试练习不替代源码阅读。
